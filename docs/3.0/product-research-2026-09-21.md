# Clawket 3.0 发布前产品研究与商业化建议

研究日期：2026-09-21。范围：当前 Clawket 工作区、OpenClaw / Hermes 官方更新、App Store / Google Play 产品页、GitHub 源码与说明、Clawket PostHog 聚合事件。

**性质：供负责人决策的研究提案，不是新增实施规格。** 本次用户明确要求重新研究功能与付费策略；下文与现有冻结决策不同的部分均为建议，未修改免费额度、价格、会话限制或实现计划。没有部署、购买竞品、修改后端配置或改动外部 Hermes 源码。

**同日交互核对更正：** 当前聊天加号菜单已经有新建定时任务，并将输入框草稿通过 `cronPrompt` 带入编辑器。原报告将草稿预填列作新增功能不准确；下文“聊天转定时任务”的新增范围仅指从已完成、多轮调整的对话提炼独立任务，经用户确认后创建。现有草稿入口见 [ThreadScreen](../../apps/mobile/src/screens/Thread/ThreadScreen.tsx)。这一增强不应挤占更明确的发布前缺口。

## 1. 建议先做什么

**Clawket 最有机会赢的地方，是让用户在手机上完整地交办、跟进、完成 OpenClaw 和 Hermes 的任务。** 漂亮的聊天界面已经是优势；下一步需要把技能、记忆、自动化和模型能力连接到聊天中，让用户完成更多事情，同时让 Pro 的价值自然出现。

五个核心判断：

1. **Hermes 不是从零补管理页。** 当前已接入技能管理、定时任务、全局模型切换、记忆文件读写。主要缺口是入口、操作闭环、原生能力对齐和高级交互，不能把已有功能重新排成“待开发”。
2. **OpenClaw 的变化已经超出聊天 UI。** 新方向包括运行中干预、跨会话记忆、技能迭代、自动化结果管理、原生手机入口。逐页搬运管理控制台的收益，低于把这些能力变成聊天里的下一步操作。
3. **双后端体验一致是差异化，但并不意味着能力相同。** 用户应知道能做什么、操作影响哪里；例如 Hermes 切模型影响全局，不能包装成单会话设置。
4. **优先检查付费时机与价值表达，再增加收费点。** 首次得到回复前弹墙、把非主会话压成两条只读消息，可能削弱聊天主产品的体验。这是待验证假设，现有数据不能证明放宽后必然增收。
5. **稳定性与收款可观测性高于新功能数量。** 收不到结果或付款状态不清时，更多功能无法弥补损失。

### 推荐发布组合

| 阶段 | 建议交付 | 用户能感知的变化 | 商业作用 |
|---|---|---|---|
| 3.0 发布门槛 | 正式环境双后端稳定性、购买/恢复购买、后台与冷启动结果恢复 | 出门也敢把事情交给 Agent | 减少流失、退款与低分 |

## 3. 自身能力：真实缺口在哪里

### 3.1 当前产品不是只有 UI 改造

| 能力 | OpenClaw 当前状态 | Hermes 当前状态 | 应补的具体缺口 |
|---|---|---|---|
| 聊天、停止、历史、图片 | 已有 | 已有 | 验证弱网、恢复、流式与终态一致性 |
| 消息排队 | 已有本地队列，可调整/移除，停止或错误时暂停 | 共用能力 | 不等于原生运行中 steer；需要清楚区分 |
| 非图片文件发送 | 能力已声明支持 | `fileAttachments=false` | Hermes 文档/PDF 等需新适配与大小/类型处理 |
| 会话管理 | adapter 有创建/重命名/重置/删除 | adapter 同样有 | App 未提供新建会话入口是产品决策，不是后端不能做 |
| Skill | 查看、开关、编辑、删除、发现、安装入口已有 | 同类基础能力已有 | 原生来源、安装完成校验、直接使用、更新审查 |
| 定时任务 | CRUD、立即执行、运行记录；高级能力较全 | CRUD、立即执行、运行记录已有 | Hermes 每任务模型、时区/高级选项尚未完整转发；不能用全局时区冒充 |
| 模型 | 会话选择与配置管理已有 | 全局模型/思考等级选择已有 | Hermes Provider 健康、凭据状态、辅助模型/回退配置 |
| 记忆 | 文件入口可读写 | `MEMORY.md`、`USER.md` 可读写 | 可发现、可理解的入口；区分文件与完整记忆系统 |
| 工具与子任务过程 | 已有工具卡、子任务卡与结果保留 | 有共享过程展示 | 原生审批/澄清、结果整理、跨离线状态衔接 |
| 搜索/收藏/分享 | 本机已缓存内容搜索、收藏、对外分享海报已有 | 共用能力 | 接收系统分享是另一功能；跨连接/归档检索还需设计 |
| 通知 | 存在本机 `system.notify` 处理 | 不等于后台推送服务 | 缺少完整 APNs/FCM 远程任务完成/待处理闭环 |

### 3.2 OpenClaw：优先对齐对话过程，而非完整复制控制台

| 上游近期变化 | 对 Clawket 的产品意义 | 建议 |
|---|---|---|
| 新 Web UI 的运行中 steer、队列与更清楚的工具过程 | 用户发出新要求时，要知道它会影响当前任务还是下一任务 | 高优先：明确“补充本次任务 / 排队下一条”；仅对协商支持的版本开放 |
| 跨会话记忆搜索、查看与遗忘 | 用户需要知道 Agent 为什么记得某件事，以及怎样纠正 | 高优先：先做可读入口；原生检索/遗忘随后接入 |
| Skill Workshop、提案、检查与审查 | 技能从静态插件变为重复工作的积累 | 先让已安装技能好找、好用；再做生成技能与变更审查 |
| Automations 产品化、克隆/暂停/运行结果 | “每天替我做”是聊天形成习惯的入口 | 先聊天转任务与结果卡，再补高级调度 |
| 原生分享、语音与手机入口 | 不能只等用户主动打开 App | 系统分享优先 URL/文本；现有语音先把可靠性做实 |
| 新版分享、归档、实时通话、协作浏览等 | 部分是结果流转，部分是大范围新产品 | 归档与分享值得跟；会议/电话/协作浏览不进此次发布 |

上游来源：[新 Web UI](https://docs.openclaw.ai/releases/2026.8.1/the-new-web-ui)、[记忆](https://docs.openclaw.ai/releases/2026.8.1/memory)、[技能](https://docs.openclaw.ai/releases/2026.8.1/skills)、[自动化](https://docs.openclaw.ai/releases/2026.8.1/automations-and-scheduling)、[原生 App](https://docs.openclaw.ai/releases/2026.8.1/native-apps)、[2026.9.5](https://docs.openclaw.ai/releases/2026.9.5)。

三处容易误判的兼容性问题：

- 上游把产品叫 Automations，**不意味着必须把现有 `cron.*` 协议推倒重来**；官方仍保留兼容入口。
- 跨会话记忆不等于一个 `MEMORY.md`。遗忘派生记忆也不等于删除原始聊天，应说明范围。
- Fork/rewind 不能笼统宣传成“撤销 Agent 的操作”。会话分支、上下文恢复、磁盘或外部操作回滚是不同能力；有些上游操作限定特定运行环境。

### 3.3 Hermes：把四项基础功能做成可信的日常工具

**技能：从列表管理走到实际使用。** 当前发现页聚合 ClawHub 与 skills.sh，安装通过发消息让 Agent 执行命令。建议接入 Hermes 自身的 Hub 语义，标注来源、版本和安装状态；安装结束再次查询确认，失败保留可理解原因；已安装技能出现在聊天“使用技能”入口。不能把任意第三方 slug 直接当成可靠的 Hermes 安装标识，也不能假定 App 发送 `/技能名` 就具备终端中的原生命令分发。Hermes 文档支持多个技能来源与安装检查，适合作为兼容层依据。[Hermes Skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)、[Quickstart](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart)。

**定时任务：从“有 CRUD”走到“我知道它会怎样执行”。** 现有聊天加号已支持草稿预填新任务；可选增强是从已完成对话提炼包含最终要求的独立任务，再由用户确认时间、时区、执行提示和结果去向。执行成功、结果投递成功、用户已读要区分。高级 per-job 参数只有经过 Bridge 转发和运行验证后才展示；Hermes 全局 timezone 已存在，不代表当前 Clawket 已支持逐任务时区。[Hermes Cron](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron)、[Configuration](https://hermes-agent.nousresearch.com/docs/user-guide/configuration)。

**模型：先明确“现在用什么、是否能用、影响哪里”。** 保留现有免费全局切换，补 Provider 名称、凭据是否配置、错误原因和小规模连接测试。下一步才提供默认/回退、辅助模型与高级路由。切换前提示“影响此 Hermes 的全局模型”；不引入每会话模型状态。主模型与视觉/压缩等辅助模型可能不同，不要给用户虚假的“一处切换全部改变”。[Configuring models](https://hermes-agent.nousresearch.com/docs/user-guide/configuring-models)。

**记忆：先把现有能力摆到用户能找到的位置。** 设置中直接出现“记忆”和“关于我”，分别解释当前文件内容、用途及保存时间。默认可读，支持基础纠错/删除；完整 Markdown 编辑、版本差异与恢复可作为高级管理。后续再按能力连接可选记忆 Provider 与待审核写入。官方文档的写入审批有配置前提，不应宣称默认全部开启；批准/拒绝等控制动作不应收费。[Hermes Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)。

官方 Web Dashboard 已提供技能 Hub、模型、记忆、Cron、MCP 等管理接口，说明这些功能有原生语义可参考；**不等于 Clawket 当前 Bridge 已经使用这些接口**。现有 Bridge 路径、鉴权与生命周期不同，应先做接口复用调查，再确定接入成本。[Web Dashboard](https://hermes-agent.nousresearch.com/docs/user-guide/features/web-dashboard)。

### 4.3 对竞争格局的判断

“有聊天、有技能页、有 Cron 页”逐渐成为基础配置；官方客户端也在进入这些领域。Clawket 更可持续的组合是：**双后端 + 原生手机使用习惯 + 稳定的任务交付 + 清楚的结果和控制权**。

不建议以“功能数量最多”作为目标，也不建议只强调“更漂亮”。商店上架图应演示具体任务，例如“把这篇文章交给 Hermes”“让 OpenClaw 每天整理简报”“出门后收到完成提示”，并且只展示发布包已经可用的功能。

## 5. 功能建议与实现优先级

成本是相对范围，尚未做工程排期：S 为局部入口/组合，M 为跨页面或 adapter 的完整链路，L 为协议、原生系统或服务端生命周期变化。**P0 不等于允许压过稳定性发布门槛。**

| P0 / S | Hermes 记忆入口 | “记忆/关于我”直接可达；真实读回、空态、保存失败可理解 | 阅读免费；基础纠错建议免费；高级编辑/版本 Pro |
| P0 / S–M | 已安装技能→聊天使用 | 显示实际可用技能；选中后进入草稿并明确作用；不能只发送无效 slash 文本 | 基本使用免费 |

### 三个适合演示的小闭环

1. **用技能完成一次任务：** 打开聊天 → 点“使用技能” → 选已安装技能 → 填一句需求 → 看执行与最终结果。后续才引导“把这套方法保存为技能”。
2. **把一次成功变成每天自动做：** 某次简报完成 → 点“定时执行” → 确认每天 8 点及当前时区 → 查看下次运行。前期不需要复杂自动化编排器。
3. **修正 Agent 对我的认识：** 聊天里发现偏好错误 → 打开“关于我” → 找到并修改对应内容 → 明确下次生效范围。后期才做多记忆 Provider 检索。

### 当前没必要做，或至少不应挤进 3.0

- 手机 IDE、完整终端、Git worktree、代码审查平台：维护与交互成本高，会稀释聊天主线。
- 新增所有 coding agents 或任意代理框架：先把 OpenClaw/Hermes 做深。
- 托管 Agent 云电脑、代售大模型积分：改变商业模式和持续成本，不能因同名 PocketClaw 有订阅就照搬。
- 图形化多 Agent 编排、庞大模板市场、公开社交广场：尚无本产品需求证据。
- 全套手机节点/传感器、穿戴端、实时电话会议：保留现有兼容能力即可，不在本次拓宽。
- 把所有 MCP/Provider/工具配置原样搬到手机：先提供状态与少数高频操作，避免移动版配置文件编辑器。
- 手机一键升级远端 Agent 并承诺自动修复：涉及服务中断、权限和恢复，先提供诊断与明确指引。
- 3D 宠物或重动画作为主卖点：现有视觉已获认可，投入应转向任务完成率。

### 实施边界

新增能力必须进入集中 capability 契约，由各 adapter 声明和运行时降级；不因 Hermes 上游出现某接口就直接对所有安装开放。新旧客户端与双后端都要验证，不改变外部 Hermes 源码。

推送是新增服务能力：当前本机通知不具备远程送达保证。建议只发送“任务完成/需要处理”和不含内容的路由标识，正文在认证连接后读取；不为通知把聊天内容持久化到 Relay。它需要单独的规格与隐私/设备注册方案，应在 3.1 范围处理。

归档与恢复也不能通过随意改写 Hermes 原生会话数据库实现；维持只读边界，优先使用已验证的原生能力或 Clawket 自己的索引。

## 6. 付费墙审查：哪些地方值得保留，哪些值得实验

### 6.1 当前真实规则

| 项目 | 当前规则 | 判断 |
|---|---|---|
| 免费对象 | 一个连接、默认 Agent；免费连接最多每 24 小时切换一次 | 多连接/多 Agent 是自然升级点，值得保留 |
| 主会话 | 完整聊天与历史免费 | 正确，不要把它误写成所有聊天收费 |
| 非主会话 | 仅最近两条用户/助手正文，只读、无分页/工具过程，回复受限；待处理审批仍可操作 | 与核心聊天价值冲突风险最大，值得单独实验 |
| 搜索 | 可搜设备缓存；打开完整消息详情触发 Pro，非主会话预览也受限 | 容易出现“自己的内容找到了却打不开”感受 |
| 模型 | 聊天中的模型选择免费；OpenClaw 管理写动作 Pro；Hermes 当前是免费全局选择 | 保留选择能力，不把不同模式混为一谈 |
| 管理 | 文件保存、OpenClaw 配置/权限详情/日志/备份、长期用量等收费 | 高级管理可以收费；基础排障与安全控制应足够可用 |
| 触发 | 每个冷启动进程首次 ready 且 Roster 渲染后 500ms 自动弹；不是每次切回前台；审批优先 | 对新用户可能早于第一次有价值聊天 |
| 预览与购买 | 多处最后一步拦截，真实数据预览；购买/恢复后原地续做 | 已经做得对，保留 |
| 旧用户 | 特定已有多连接/非主 Agent 用户有一次 14 天宽限 | 不是所有人的试用；不能当成完整新用户体验期 |

依据：[付费规格](06-paywall-and-growth.md)、[会话预览规格](21-session-preview-pro.md)、[预览计算](../../apps/mobile/src/utils/session-preview.ts)、[启动付费墙](../../apps/mobile/src/navigation/launch-paywall.ts)、[模型页](../../apps/mobile/src/screens/AgentSettings/ModelsScreen.tsx)。价格、弹墙、非主会话和新建入口均有近期负责人决策；以下只是本次研究提出的复核建议。

### 6.2 建议的免费与 Pro 边界

**免费版应该让用户完整完成一个真实任务；Pro 应增加规模、长期积累和高级控制。** 不建议把基础安全、错误恢复和取回自己刚得到的结果变成收费理由。

| 建议免费 | 建议作为 Pro 核心 | 持续成本服务单独设计 |
|---|---|---|
| 一个连接/默认 Agent 的好聊天体验 | 多连接、多 Agent | 托管语音转录的合理额度 |
| 基础模型切换、技能使用、基础任务 | 跨连接检索、归档组织、批量导出 | 实时语音/语音合成若引入需成本核算 |
| 阅读记忆、必要纠错与删除 | 完整文件编辑、版本差异与恢复 | 不把新服务无限额度默认塞进旧买断 |
| 审批、停止、澄清、重试、连接诊断基础 | 高级配置、备份/恢复、长期用量 | 若有 BYO 服务，可提供用户自付成本路径 |
| 基本附件/分享、查看当前任务完整结果 | 自动化高级管理、模板复用、多对象批量操作 | 额度必须由服务端可信校验 |
| 基础完成/失败/待处理通知（建成后） | 通知规则、汇总与多连接筛选 | 避免“升级才能知道审批卡住”的设计 |

“高级自动化 Pro”指新增的高价值管理层，不建议突然把现有免费 Cron CRUD 全部收回。类似地，记忆纠错可以是专用、受限动作，与任意 Markdown 文件编辑区分；删除自己的内容和必要的安全处理不应被锁住。

### 6.3 最值得验证的四个改变

**第一：改变首次自动弹墙时机。** 新用户先配对、发出消息、收到一次真实完成回复；用户空闲时再轻量展示 Pro。第二连接、其他 Agent 或高级管理等高意图操作继续情境触发。后续自动提示设冷却期（例如 7 天是可测试起点），任务进行中、错误恢复时不弹。不是永远不卖，也不是延迟一周才告诉用户有 Pro。

**第二：试验更完整的基础会话体验。** 对照现有规则，试验默认 Agent 的普通手动会话可完整读写，当前任务结果免费查看；Pro 收取跨渠道/跨连接的深入整理、归档与高级检索价值。若当前无法可靠分类会话来源，先只放开明确的任务结果入口，不用 session key 猜测。此项是对现有“非主会话两条预览”决策的实质调整，必须作为独立产品实验，不能悄悄实施。

**第三：提供一次真正的 Pro 体验。** 建议在第一次成功对话后、或尝试第二后端时，提供 7 天体验。优先研究无需绑卡、到期不自动扣款的产品体验通行证；这需要可信权益与一次性发放机制。若改用 App Store/Play 订阅试用，要遵循商店资格和自动续订展示，不能宣传成无自动收费。可先利用现有受控兑换能力招募少量用户验证体验价值，再投资自动发放系统。现有 14 天迁移宽限不能取代此设计。

**第四：让付费文案匹配当前意图和后端。** 第二连接时强调“一起用 OpenClaw 和 Hermes”；查过去任务时强调“集中找到聊天和任务”；管理模型时说明具体可解锁的设置。Hermes 页面不要用其不支持的 OpenClaw 日志/权限作为首条利益。保留当前视觉、关闭/恢复入口和购买后续接，减少无关权益堆叠。

试用规则参考：[Apple introductory offers](https://developer.apple.com/help/app-store-connect/manage-subscriptions/set-up-introductory-offers-for-auto-renewable-subscriptions)、[StoreKit eligibility](https://developer.apple.com/documentation/storekit/implementing-introductory-offers-in-your-app)。

### 6.4 不要先打价格战

仓库规划价为月付 $2.99、年付 $19.99、买断 $49.99；**本轮没有读取实时 RevenueCat offering 或各地区商店后台，不能当作当前实际成交价**。App 继续使用商店本地化价格。

建议先稳定权益、首个价值体验和支付链路，再研究价格。年付面向长期用户；月付给低承诺入口；买断可以降低订阅抵触，但 $49.99 只是约 2.5 个 $19.99 年费的毛收入，不足以推导长期利润。不能由竞品 $0.99 下载或 $28.99 一次购买认定我们必须更便宜。

已有买断与历史权益应保护；若以后推出消耗型云服务，先算单位成本与额度，再设计服务权益。当前语音代理已有 admission/预算限制，200 次任务准入不是 200 次无限长录音，分段与重试也可能计数；不能把它包装成终身无限语音。参见 [语音规格](22-voice-input.md)。

也没有可靠外部证据证明“更宽松免费必然更赚钱”：RevenueCat 2026 报告中，hard paywall 的 D35 下载付费中位数为 10.7%，freemium 为 2.1%；这是不同产品群的观察，不能当作同一产品改墙的因果实验。Clawket 还要求用户先拥有/连接 Agent，更需要测本产品的激活后净收入与留存。[RevenueCat 2026](https://www.revenuecat.com/state-of-subscription-apps)。

### 应建立的指标

| 决策问题 | 指标与口径 |
|---|---|
| 是否真正用起来 | 首次后端鉴权完成 → 消息被后端接受 → 收到终态回复；分别记录，不能用 WebSocket open/发送点击代替 |
| 是否形成习惯 | 激活 cohort 的 D7/D28 有效聊天或任务结果消费；区分 OpenClaw/Hermes、平台、版本 |
| 是否更会赚钱 | 随机实验用户 D35 每合资格用户净收入；商店/RevenueCat 对账，计退款和服务成本；付费率是辅助指标 |
| 付费墙是否工作 | 同一身份有序的曝光→点击→已核实权益；约定 7 天归因窗口，试用另看成熟 cohort |
| 新功能有没有价值 | 技能实际使用成功、任务保存后首跑完成、分享输入到回复、结果打开/保存；不是页面浏览数 |
| 是否牺牲体验 | 回复完成率、失败重试、后台恢复、退款、支持求助与 D7 留存 |

推荐北极星代理指标：**每周至少完成一次有价值手机任务的用户数**。先用终态结果加明确后续行为（继续对话、保存、分享、处理审批）作代理，避免采集正文来“判断价值”；承认它不是对用户满意度的直接测量。

### 实验顺序

1. 先验证事件和真实商店收款链路；把取消、pending、技术错误分开。
2. 实验首次弹墙时机，其他权益和价格保持一致。
3. 再实验非主会话/任务结果的免费边界。
4. 再评估一次 Pro 体验，最后才实验价格/套餐默认项。

当前 30 天仅记录 5 个购买成功标识，不能同时做多组小流量实验，还承诺两周显著。按稳定用户身份分组，预先约定主要指标与观察窗口；付费结果不足时，用真实任务测试和少量访谈补充，不把点击提升当收入提升，也不因短期波动立即宣布胜出。

## 8. 可执行的下一阶段清单

### 发布前必须关闭

- 正式 OpenClaw Relay 问题按现有发布/迁移恢复流程修复并复测；Hermes 同时回归，v1 回放不能红。
- 商店签名包验证购买、取消、pending、恢复购买、已有终身权益与旧版本升级；临时 Pro 解锁 QA 包不算通过。
- 语音、图片、后台恢复和关键管理操作按最新 QA 未完成项验收；不要将代码能力表当作已实测列表。
- 更新 Pro 文案与真实后端能力的一致性；确认安装 Skill、保存 Cron、切模型后能读取真实结果。

### 面向用户的增量候选（更正后）

1. **聊天里使用技能**：优先已有安装技能的发现与可靠调用。
2. **已完成对话转成定时任务（后续增强）**：现有草稿→Cron 路径已实现，不重复开发。新增范围是提炼多轮对话的最终要求、用户确认、复用既有任务创建；优先级下调，不作为发布前必加项。
3. **Hermes 记忆/关于我入口**：让现有读写能力成为用户知道、敢用的功能。

技能使用与记忆入口更适合优先评估；现有聊天新建任务可直接展示为已有能力。若增强牵涉未验证的新后端协议，就移入发布后，不为凑“3.0 新功能”牺牲主聊天。

### 发布后第一个完整迭代

先做 URL/文本系统分享与结果文件闭环，补 Hermes 原生技能来源和安装状态；同步设计远程通知、审批与 steer 的 capability 契约。后者完成基础设施和双后端恢复验证后，再作为 3.1 主打。

### 需要负责人后续拍板的产品选择

这些不阻塞本研究交付，也没有被本报告自动实施：

- 是否将首次自动付费墙移到第一次成功聊天之后。
- 是否实验放宽非主会话与当前任务结果的两条预览限制；9 月 20 日“维持现状”的决定目前仍有效。
- 是否提供一次 7 天 Pro 体验，以及采用产品通行证还是商店自动续订试用。
- 是否重开新建会话入口的产品实验；不把缺少旧埋点当作否定需求的证据。
- 后台远程通知作为 3.1 新服务范围，是否进入下一阶段规格。

**推荐立场：保留一个连接的完整好体验，用多个 Agent、长期积累、高级管理和节省时间的能力挣钱。首先让用户愿意每天在 Clawket 里交办事情，再让升级带来的额外价值清晰可见。**
