# Connection latency and diagnostics

## Negotiated owner roundtrip fallback (2026-09-29)

Bridge owner and OpenClaw secondary-channel sockets may request `relay.owner-pong.v1` in the existing comma-separated capabilities query. Only authenticated opted-in sockets receive that capability in `relay.ready`; old owner/client ready payloads remain unchanged. When a WebSocket pong is missing, a supporting Bridge can verify one bounded application roundtrip using `__clawket_relay_control__:` plus `{type:"control",event:"relay.owner-ping",payload:{nonce}}`. Relay returns `relay.owner-pong` with the same 32-lowercase-hex nonce only on that current owner/channel socket. This verifies the Bridge–Relay leg, not the local Agent, mobile leg, or successful delivery of an earlier prompt.

Relay handles reserved ready/ping/pong controls after client admission and before any pairing, secondary-channel or normal forwarding. Clients, restricted tickets, replaced sockets, binary/malformed frames and unsolicited pong/ready controls cannot produce or route an owner echo. Negotiated owner/channel and full-client nonce replies share a bounded admission rule: four arrivals may burst, then credits refill at one echo per second. Independently delayed probes can arrive closer together than their send cadence. Persist consumed integer credits and a nondecreasing refill timestamp in the existing socket attachment before replying; memory discard cannot refill the bucket, legacy last-ping timestamps migrate conservatively, and invalid budgets fail closed. Preserve routing metadata and the ordinary client message budget. No nonce is logged or persisted. The owner lease and existing client-pong expiry policies are unchanged. Bridge fallback must bind a nonce/deadline to the current negotiated socket; unrelated messages cannot satisfy a pending echo.

Rare fallback diagnostics use `event=owner_heartbeat` and allowlisted `heartbeatOutcome=echo_sent|attachment_failed|send_failed|rate_limited`, only for a valid negotiated ping on the authenticated current owner/channel. They carry the existing server-generated socket diagnostic UUID and socket kind, never nonce, payload or exception text. `echo_sent` means the Relay send call returned, not that the Bridge received it; compare it with the Bridge's matched confirmation or deadline to locate the missing leg. Rate-limit diagnostics are bounded to one per fixed second using an additional timestamp marker in the same attachment, including after hibernation. Malformed and unauthorized controls produce no heartbeat diagnostic.

Cold room recovery adds `event=room_initialization` only for failure or total duration ≥1,000 ms. `initializationOutcome` is `ready|error`; `initializationStep` is the final reached stage (`room_meta|client_tokens|owner|sockets|heartbeat`). `initializationMs`, `roomMetaMs`, `clientTokensMs`, `ownerLoadMs`, `socketsRehydrateMs` and `heartbeatSetupMs` are clamped to 0–60,000 ms. No error text, nonce or new identity is recorded. Initialization preserves the serial credential/owner reads, authenticated socket rehydration and awaited heartbeat setup inside `blockConcurrencyWhile`. These `Date.now()` differences are **I/O-stage wall time**, not CPU execution time: Workers clocks advance at I/O boundaries, and this instrumentation cannot see queue/wakeup delay before the constructor or output-gate delay after the last observation. A missing slow-init event does not prove instant platform wakeup. Invocation logs and traces remain disabled.


The five Agent runtimes retain their existing probe cadence (OpenClaw 10 seconds; Hermes/Codex/Claude Code/Pi 15 seconds). Negotiated sockets send an exact-nonce protocol ping first, then hedge after 1 second without proof using one application echo. Both share the same original deadline capped at 5 seconds; explicitly shorter settings remain shorter. Either current-cycle/current-transfer-generation reply confirms once and cancels both pending legs. A protocol pong within 1 second generates no application message; the hedge delay is not a health threshold. Probe cadence is unchanged. Without a pending large-frame allowance, nominal failure detection is at most 15 seconds for OpenClaw and 20 seconds for the other four from a blackhole just after a healthy pong; process scheduling and subsequent authentication add latency, so these are not mobile recovery guarantees. Large transfers retain their existing absolute dual-clock allowance, never a new second timeout. Bridge hedge start/confirmation logs are limited to one pair per socket per minute; timeout/send failures remain immediate. Their `waitMs`/`rttMs` retain application-leg timing when sent (`waitMs` uses the cycle if no application probe was sent); timeout `cycleWaitMs` separately measures the complete cycle from the protocol ping. Historical records retain their original meaning. Missing successful diagnostics do not establish continuous health. Old Relays and the local-model probe cadence retain their original liveness rules.

After abnormal transport loss (1006), a negotiated socket that previously confirmed a round trip can spend one first retry with 0–250 ms jitter, capped by its existing delay. Its same-process owner identity is unchanged; the next socket must obtain fresh round-trip evidence before another fast retry. Lease conflicts, explicit replacement, admission rejection and manual stop retain existing rules. No business request is replayed. Fresh HTTPS health or a Relay-local send does not establish that an existing WebSocket or local Agent is healthy, and an on-demand command sent through a blackholed socket cannot guarantee immediate owner recovery.

## Incident and recovery

On 2026-09-07, the physical iPhone Preview pairing took 46.621 seconds from Bridge client demand to final authentication. Initial bootstrap authentication took 34 ms. Two replacement local Gateway sockets received no connect request and each reached OpenClaw's 15-second handshake timeout. After the cloud Relay owner connection recycled, device-token authentication took 24 ms. History took 71 ms. These timings identify the stalled handoff, not the original packet-loss/routing trigger.

Mobile setup deliberately connects as a node to obtain device credentials, then reconnects as an operator. Do not remove this role separation to improve apparent speed. The client now recognizes a different challenge after readiness as a backend replacement, authenticates again, and ignores duplicate challenges. The Bridge now detects a forwarded challenge with no connect request after eight seconds and recycles the complete Relay owner path, preserving backoff. Bootstrap issuance suspends this watchdog; successful request forwarding and connection disposal cancel it. This is bounded recovery, not a guarantee that all networks will connect within eight seconds.

Historical cloud availability depends on configured retention; `wrangler tail` only captures new events. Do not claim a historical query was performed when only local logs were read.

`connect_phase` contains only protocol (`challenge` or `health`), route (`relay` or `direct`), phase, attempt ordinal, elapsed milliseconds since socket open, and milliseconds since the prior phase. Phases: `socket_open`, `challenge_received`, `credentials_ready`, `authenticated`, `bootstrap_handoff`, `backend_restarted`, `ready`, `reconnecting`, `closed`, `error`. Existing failure events carry normalized failure codes. The phase event has no URL, raw ID, nonce, token, payload or message. Its elapsed time excludes pre-socket DNS/TLS/Registry time; use the coordinator's `connect_ready` for broader connection duration.

Relay `diagnosticId` is a fresh server-generated UUID per accepted socket, retained in its attachment across hibernation. It links `ws_connected`, `challenge_delivered`, `connect_start_forward`, `connect_response_delivered`, and `ws_disconnected`. It is intentionally not a durable device/user identity and is not an end-to-end App/Registry/Bridge trace ID. Existing sockets from older deployments may have no marker. Raw identity fields remain filtered; malformed diagnostic markers are rejected. Deploy the Relay change before expecting this field in cloud logs.

Mobile `transport_diagnostic` records the first error and actual remote close of the current socket attempt separately from recovery intent. Its allowlisted fields are backend, transport, environment, event, transport phase, stable code, optional numeric close code and elapsed milliseconds from socket construction (capped at 24 hours). It records no URL, peer reason, exception text or new identity. Retired-socket callbacks are ignored and observer failure cannot affect transport behavior. `reconnect.origin` says which recovery path acted; `reconnect.cause` retains the observed timeout/close category even when the legacy `reason` remains `probe_failed`. Neither a probe origin nor code `1006` identifies the failing network component. Initial activation diagnostics and these later socket-attempt diagnostics are distinct coverage.

## Triage sequence

1. Establish App version, CLI version, backend, service environment, and incident time/timezone. Debug Mode selects Preview for new official OpenClaw pairing; Hermes has isolated infrastructure. Never infer environment from “dev build”.
2. If there is no socket open, check Registry invitation resolve/claim HTTP status and App failure events. Distinguish environment rejection, expiry/single-use claim, DNS/TLS/offline, and HTTP error. Do not retry by refreshing credentials before preserving evidence.
3. Match the Relay socket by incident window and `diagnosticId`. Compare challenge delivery and connect forwarding. A delivered challenge without a forwarded connect points to client/transport recovery; no cloud challenge points toward Bridge/local Gateway or cloud routing.
4. Compare Bridge `phase=challenge_forwarded`, bootstrap `elapsedMs`, connect forwarded/response timings. `code=connect_request_missing action=relay_recycle` means the eight-second watchdog acted, not that authentication itself was slow.
5. If authentication is fast but UI remains loading, inspect session/history/model request timings and App ready events separately. Do not label all startup latency “connection time”.
6. Preserve a credential-free timeline with UTC timestamps, evidence paths, proven facts, hypotheses and deployment versions. Never attach pairing code, QR payload, bearer token, decrypted invitation, device private key or chat content.

For live Preview capture use `npm run relay:tail:preview-worker` or `npm run relay:tail:preview-registry`. Hermes Preview has separate `relay:tail:hermes-preview-worker` / `relay:tail:hermes-preview-registry` commands. Read the Wrangler skill before CLI use and inspect the resolved config; never substitute Production bindings.

## September 28: privacy-preserving failure attribution

The owner requires minimal connection diagnostics, with no chat or actual request/response data retained. The new source changes below are locally verified, not a claim of rollout to TestFlight, installed Bridges or Production Workers. Existing telemetry cannot reconstruct evidence that was never recorded. The owner's recovery after network conditions improved is supporting evidence, not proof of the exact earlier fault. The incident's historical `bridge_offline` and `network` labels must not be interpreted as established root causes: generic handshake timeouts and unknown exceptions previously received those labels.

| Surface | Added or tightened evidence | Privacy boundary |
|---|---|---|
| Mobile `connection_diagnostic` | Initial connection or QR claim outcome; backend, transport, environment, phase, duration, stable code; HTTP status when received; failure-only OS path category | Every string uses a finite allowlist. No URL, IP, SSID, device label, pairing value, payload or new identifier. Uses the existing analytics configuration/identity; this is not a new anonymous-identity scheme. |
| Local Mobile diagnostics | UTC timestamp for each of the existing last 20 semantic events | Bounded in-memory history; no new persisted log or transcript store. Existing SDK delivery queue is unchanged. |
| Relay application logs | Backend and `ownerConnected` on runtime events, alongside existing socket kind, close code and age | Replace field blacklist with a typed field/value allowlist. Drop unrecognized fields and peer text, including old derived trace hints. Preserve only existing server-generated per-socket UUIDs. |
| Registry application logs | Backend, normalized route, HTTP method/status and elapsed time | Unknown routes become `/:unmatched`; unknown methods become `OTHER`; token-sync transport exceptions become `transport_error`, never raw exception text. |
| Codex Bridge local log | `native_rpc_diagnostic`: spawn/exit/write failure, invalid/oversized frame, timeout or deliberate stop; pending count and optional bytes | No native frames, method/params, stderr, exception strings, paths or session IDs. No automatic local-log upload. |

No new probes, sockets, timers for polling, retry loops, third-party endpoints, production observability settings or retention extensions are introduced. OS sampling runs only after failure and is abandoned after one second for diagnostic purposes; it never delays or rejects the connection. The native OS read may finish later; its late result cannot overwrite the published evidence. iOS `isInternetReachable` aliases path availability in the installed module, so it is intentionally not used as proof of Internet access. Mobile success does not sample OS state. HTTP evidence takes precedence over a later offline snapshot; a response proves that exchange reached an HTTP responder, not that all services or the response body are healthy.

### Evidence and permissible conclusions

| Evidence | Conclusion and next action |
|---|---|
| Failed operation, no HTTP response, timely OS snapshot says disconnected | “The phone reported no available network path at failure.” Ask to restore connectivity/switch networks; do not infer whether Wi-Fi, VPN or carrier caused it. |
| HTTP 401/403/409/410/429 | The HTTP responder was reachable and rejected the operation. Investigate auth, used/expired invitation or admission using the exact status; do not call it generic phone network failure. |
| HTTP 2xx headers, body deadline expires | Response transfer or parsing did not complete. Keep `phase=body`; headers alone do not prove full service health. |
| Authenticated Relay rejects a request with `BRIDGE_UNAVAILABLE`, same socket/time has no owner | Computer-to-Relay/Bridge availability issue. Check the computer's local runtime and Relay owner history; this is not proof of a phone network failure. |
| `native_rpc_diagnostic` reports invalid/oversized frame or native exit | A local Codex App Server boundary failed. Inspect fixed reason/count evidence, not transcripts. `stopped` is intentional shutdown, not an outage. |
| Timeout, WebSocket 1006, or Wi-Fi/cellular path available | Cause remains `unconfirmed`. Check endpoint-specific failures, edge/cloud health and computer logs; OS path availability is not a connectivity probe. |
| Switch network/VPN and retry succeeds while relevant cloud/Bridge health stays stable | Strong evidence of a path-dependent failure. Report the observed comparison; do not claim to distinguish DNS, TLS, proxy, carrier and edge without corresponding measurements. |
| No matching cloud request | Insufficient evidence: request may have failed before Worker execution, logs may be absent, or the selected window/service may be wrong. |

A cloud owner replacement storm is a separate diagnostic pattern. The September 28 Hermes replacements are not explained by a blanket “users have bad networks”; installed versions/supervisors must be matched to the affected installations before choosing a cause.

### Negotiated owner cadence with connected full clients

The five Agent owner transports use 5-second protocol probes while the current authenticated Relay reports at least one full client. OpenClaw secondary channels follow the same rule; an empty or unknown population keeps the original idle cadence (OpenClaw 10 seconds, Hermes and the SDK backends 15 seconds). This is socket presence, not an assertion that a phone is foreground. Legacy peers, local-model, and Mobile’s existing 15-second application-ping cadence remain unchanged. Presence changes never reset a live 5-second round-trip deadline or a 90-second transfer allowance, and repeated count changes can only move an already scheduled probe earlier.

At a continuously active socket, Hermes/SDK protocol pings increase from 240 to 720 per hour and OpenClaw from 360 to 720; healthy protocol pongs have the same count. Fast protocol replies still avoid application echoes and do not wake the Durable Object. Actual TLS/TCP overhead, battery and billing differences have not been measured. A lost round trip is nominally detected within 5 seconds of cadence plus its existing 5-second probe deadline, excluding event-loop delays, bounded large transfers and reconnect/authentication time; this is not an end-to-end SLA. If a new client arrives while an idle owner’s socket is already blackholed, the presence update may itself be lost and cannot accelerate that owner. No extra demand control channel, write replay or ownership-lease change is introduced.
