# 3.0 老用户 Bridge 升级引导评估

结论：对经过 Clawket Bridge 的老连接推荐升级到 3.0，不强制阻断已有聊天，不要求删除连接/重新扫码。云端升级不会升级用户电脑上的 npm 包或运行进程。用户可先升级 App，Bridge 升级后正常重启并由 App 自动重连；既有配对记录保留。

## 已核对代码

- OpenClawAdapter 每次握手重新协商 bridge.capabilities.v2，并对符合条件的旧端错误进行一次兼容回退；旧模式不会永久隐藏后续升级。OpenClaw 基础聊天/历史/会话继续调用原生 Gateway，不因旧 Bridge 整体关闭。
- 新 Bridge 协商 bridge.client-sockets.v1，给每个客户端独立本地 Gateway 通道；旧 Bridge 不具备该隔离，不能获得对应多端连接改进。
- Bridge 的会话引用文件读取、原生缺失时的技能文档读取/编辑补充，仅在认证、隔离的本地 Gateway 通道提供。旧 Bridge 缺少这些补充；原生 Gateway 自己支持的操作不应被一概宣布不可用。
- Hermes health 按能力降级多会话、新建/重命名/重置/删除，以及会话文件、运行中调整、文档附件、审批、模型健康等。具体限制取决于旧版本声明的能力；升级 Bridge 也不能保证旧版原生 Hermes 支持全部功能。
- 新修复解决了 SQLite OpenClaw 主机向旧客户端发放无效旧 JSON bootstrap 凭据的问题。已认证存量连接不等于必受影响；新设备/重新配对/重新认证需要单独考虑，不能承诺任意旧主机组合完整可用。

## 已实现的最小引导（2026-09-22）

- 3.0 更新公告仅在存在已确认的旧 Bridge 连接时，增加“更新电脑上的 Bridge”入口。其他用户仍看到原来的五条更新说明。设置首页在“我的连接”下方直接显示同一个指南入口，整行可点击；连接详情也保留该入口。错过公告后无需深入连接详情才能升级。三个入口共用旧 Bridge 判断，升级后一起消失。
- 判断来源是认证成功后的 Bridge 版本/能力，不使用云 Relay 或原生 Gateway 的版本。OpenClaw 只检查 Relay 连接；Hermes 检查本地和 Relay。无版本的成功握手按对应的新能力标记识别旧协议。尚未成功连接、只有保存日期或 roster 缓存的记录不推测为旧版。
- 使用已有 OpenClaw 握手能力缓存，并持久化新的、无凭据的 Bridge 世代记录，支持已确认旧连接离线时查看指南。新握手优先于缓存；升级后自动撤掉建议，删除连接也删除相应记录。不会为了检测版本主动唤醒其他连接。
- 指南复用连接页的标题、步骤、命令块和按钮：复制命令、系统分享发送到电脑、返回 App。提醒等待当前回复结束再更新；保留配对，不要求 reset、删除连接或重新扫码。不增加强制弹窗，也不以点击按钮作为升级成功证据。

```sh
npm install -g @p697/clawket@3.0.0
clawket restart
```

Docker/自定义服务使用原部署方式更新和重启。页面不在手机上执行命令，也不执行新的发布操作。

## 验证

覆盖两种后端的新旧握手、非 Bridge 连接排除、未知记录不误报、离线旧记录、升级清除、删除清除、历史能力缓存迁移，以及公告入口的条件展示和点击。19 种语言包含提示和指南文案。

使用独立 iPhone 模拟器渲染真实页面组件（旧 Bridge 条件作为预览输入），并通过原生点击核对复制出的完整命令。截图保存在 `docs/3.0/evidence/bridge-upgrade-ui-2026-09-22/`。这属于 UI/交互验证，不冒充再次完成 npm 升级或生产后端验收。
