# 23 · iPad 自适应工作区

负责人于 2026-09-19 批准 iPad 双栏方案并授权模拟器和本机 OpenClaw / Hermes 实测。此章扩展现有花名册与线程布局，不改变后端能力、付费规则或单活动连接策略。

## 布局与状态

- 仅 iPad 使用自适应工作区。可用窗口宽度至少 900 pt 且按字体缩放折算后至少 720 pt 时显示 300 pt 花名册和内容区；其余窗口使用单栏。iPhone / Android 保持原导航。
- 宽屏首屏在右侧提示选择 Agent；点行进入现有 Thread 路由。线程左上按钮收起/展开花名册；窄窗口中打开遮罩抽屉，点背景或切换目标后收起。旋转恢复用户的宽屏收起偏好。
- Navigator、当前 Thread 和输入组件不因断点或侧栏变化而重建。窗口变化保留当前会话、草稿和运行；阅读位置沿用现有列表，长消息重新排版后的定位仍需真机确认；不同会话继续沿用现有缓存和草稿机制。
- 侧栏复用 RosterScreen 的搜索、添加、Pro、连接管理、置顶和权限检查。选择态按 connectionId + agentId + sessionKey 识别。其他连接仍显示缓存，不能当成全部实时在线。
- 聊天行宽上限 760 pt，输入区与消息内容对齐；图片排版依据内容区宽度计算。设置和引导内容限制在 760 pt 内，保留原页面返回行为。
- iPad 宽度至少 600 pt 的 Sheet 继续复用已有的居中、分离面板（最大 640 × 720 pt）；窄窗口使用原底部弹层。修复旧最小尺寸导致的窄窗口越界。会话面板仍按需打开，没有常驻第三栏。
- 居中面板必须在整个动画容器上裁切四角；仅给背景设置圆角无法约束同级的不透明内容和固定页脚，可能使底角被盖成直角。手机与窄窗口保持原弹层边界。

## 平台与输入

- iPad 声明四个方向并允许多任务窗口；iPhone / Android 的竖屏设定保留。由 app.json 的 iPad 专用 Info.plist 键生成，禁止手改生成目录。
- 输入沿用 composition-safe 控件：Enter 换行，发送按钮发送，支持现有文字选择/粘贴及图片粘贴。此阶段未加入 Cmd+Enter 原生快捷键、跨 App 拖放或同 App 多窗口聊天。
- 配色、字号、44 pt 点击目标、后台恢复与双方后端能力遵循原规范；不引入新依赖或新聊天运行时。

## 验证

自动回归覆盖：断点与大字体、旋转/侧栏切换不卸载聊天、草稿保留、抽屉关闭、手机导航不变、小窗口弹层界限、原生四方向与窗口配置损坏检测。继续跑 Mobile 全量、类型、设计系统、文档和仓库 required 门禁。

验收矩阵包括宽/窄与横/竖、明暗主题、键盘、会话切换、设置返回、OpenClaw 和 Hermes 发收消息与恢复。已完成的模拟器检查、独立后端实测与未完成项分别记录在 PROGRESS.md；不得把纯 UI/录制协议测试或独立 Bridge 测试当成 App 端到端成功。

## 配对键盘排查（2026-09-20）

真机反馈无外接键盘时首个配对输入可聚焦但无键盘，切到其他 App 再回后键盘出现但遮挡输入。iPad 禁用 KeyboardProvider 的隐藏输入预热，配对滚动区使用原生键盘 inset / 焦点避让，关闭该页重复的 controller padding 和手动 reveal；手机路径保留。前者为针对原生首次 responder 时序风险的缓解，尚未证实为真机根因；必须冷启动复测，Fast Refresh 无法撤销已发生的原生预热。

首轮关闭预热后负责人复测仍不能唤起，不能将其写成已确认根因。第二轮 iPad 配对输入使用 `ascii-capable` + Go，绕开 iPadOS 26 浮动 numberPad；OpenClaw / 本地模型仍由原归一化函数限制数字，Hermes 保留原字母数字规则，iPhone 的 number-pad 不变。

第二轮改动后，负责人在同一台 iPad Pro 11 / iPadOS 26.4.2 真机确认“现在好了”。本次配对键盘故障已验证恢复；完整 iPad 验收矩阵中的其他待验项目保持原状态。
