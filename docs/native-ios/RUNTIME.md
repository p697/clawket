# Native backend runtime

`packages/apple/Sources/ClawketRuntime` is the native domain and connection coordinator. `apps/ios` supplies Keychain-backed device credentials, persists scoped drafts/outbox/cache, and consumes one `RuntimeEvent` stream. Screens never read the socket stream or infer backend identity from transport.

## Connection ownership

`activate` waits for authenticated backend readiness; same-record callers join it. The coordinator keeps one active connection and one retry owner, pauses retry scheduling in the background, and probes the actual backend on foreground/network hints. A WebSocket upgrade, Relay control, local send or cached roster cannot establish ready. Healthy evidence resets backoff. Reconnect never resends a prompt; `RuntimeFailure.delivery` distinguishes local rejection, uncertain delivery, a known pre-dispatch refusal and a received response.

Every operation captures activation, socket and authentication revisions. OpenClaw can issue a new challenge on the same Relay socket: retire old pending work and history chains, then authenticate that exact backend. Events include connection scope so an application can reject already-queued updates after switching connections. The application also owns its UI/history revision; actor isolation alone is insufficient.

Full clients negotiate same-socket Relay nonce liveness and large-frame protection while preserving legacy tick acknowledgments. A ninety-second absolute transfer budget survives background and same-socket authentication challenges; exact fresh echoes clear it only after actual covered dispatch/delivery. RPC, backend handshake and real health-probe waits share that bounded protection. Relay echo never establishes backend health, and bootstrap control keeps its separate twelve-second deadline. See [native liveness](LIVENESS.md) for ordering, limits and protocol sources.

OpenClaw signs the current Gateway v3 preimage using its existing TweetNaCl seed-plus-public-key identity, asks for protocol3–4 and carries Bridge capability negotiation in `caps`. Outer response `meta` remains separate from the Gateway payload. Scoped saved operator tokens take precedence. OpenClaw connect interprets exact Gateway outer/details code pairs: nested authentication and device-proof failures remain distinct from real pairing and verified-user policy. Explicit saved-device token/scope mismatch permits one captured operator-scope cleanup before readiness; cleanup failure stops recovery. Shared Gateway token mismatch, unknown codes, signature/nonce and policy failures never authorize deletion or fallback. Recovery advice and peer prose cannot grant a credential mutation. Mobile setup first receives Node/operator credentials and reconnects as operator before becoming ready. Restricted Relay bootstrap control has a cancellable send and an absolute twelve-second deadline.

Hermes uses its own `bridgeId` Relay query and real health response; degraded/unreachable API evidence fails readiness. Codex, Claude Code, Pi and local-model validate their exact `health.backend` identity. SDK direct connections authenticate using `connect`; their Relay paths use `health`, preserving OpenClaw's separate challenge lifecycle. Unavailable proven SDK backends retain the bounded short recovery sequence before slow retry.

## Native operations

The implemented surface is text send/stop/history, roster/session navigation, session creation, negotiated Codex/Claude Code projects and model selection. Hermes model selection remains global. SDK model reads retain session scope. OpenClaw global selection uses the current config hash; session selection uses `sessions.patch`. Native model switches retain their existing longer deadlines.

SDK sessions-first Agents keep an empty `mainSessionKey`; the application opens their catalog and can create a real session. A negotiated catalog is fetched completely as frozen pages, with validated revision/offset/uniqueness, 64 KiB pages, 10,000 sessions/8 MiB, 512 reads/90 seconds and one expiry restart. A failed or partial catalog never replaces the last complete roster. Delta/page-index optimizations are not advertised.

Session lifecycle uses current-row opaque references for rename/reset/delete, negotiated Codex archive/restore and native history copies. Exact backend wire shapes, ownership/active-run restrictions, non-replayed unknown outcomes and the remaining management inventory are documented in [management preservation](MANAGEMENT.md). Host menus and actual device acceptance remain separate gates.

History reads for one session serialize. OpenClaw's physical transcript offset cursor stays bound to its exact session/transcript, rather than being sent as an opaque Gateway delta cursor. Explicit run/turn/idempotency fields are retained. Wire `sentLocally` cannot grant local provenance; synthetic fallback row IDs serve presentation only and never reconcile delivery. Human activity ordering stays distinct from housekeeping timestamps.

`RuntimeMessage.providedID` preserves the exact bounded producer ID (`id`, `messageId`, then `__openclaw.id`). `idSource` distinguishes provided, synthetic and ambiguous provided IDs; missing legacy cache fields stay unknown. Repeated producer IDs retain every row and their original ID, with unique deterministic presentation fallbacks that cannot collide with a real ID on that page. Swift-canonically-equivalent IDs also receive these safe fallbacks while retaining their distinct UTF-8. Compare opaque identity keys by bytes, not display-string canonical equivalence; attribution and transcript-position equality preserve that distinction. Neither spelling, content digest, page position, text nor clock grants source/echo identity. Ambiguous IDs cannot acknowledge a send, including through an otherwise matching send key. The existing managed-image mirror projection preserves these fields and does not discard rows with ambiguous producer IDs.

`RuntimeHistory.sessionID` is optional actual top-level `sessionId`, independent of the logical route and retained thinking level. OpenClaw's typed `transcriptPosition` preserves actual source/raw sequence; `transcriptBoundary` accepts only system rows with exact structured reset/compaction kind. They do not change wire order/clocks or infer that a reset occurred from prose. Participant attribution follows [the current participant contract](../3.0/25-message-participants.md): explicit structured authors first, then bounded native sender/transport metadata and recognized channel-session fallback. Web/client transport overrides that fallback. Channel, account and sender ID remain separate from backend/transport; names, owner claims and mentions never establish the viewer. Remote avatars accept bounded credential-free public HTTPS URLs, never relative Gateway paths, private/local addresses or ambiguous legacy numeric host forms. This parser performs no avatar fetch or directory lookup.

Stream text declares delta versus snapshot and a stable assistant segment identifier. Observed tool starts create a new segment; final-only or corrected final replies remain visible without replacing earlier segments. Stop acknowledgements do not invent completion. Canonical work also exposes commentary item snapshots, tool inputs/outputs and status, producer clocks, turn/input lineage, compaction, activity, usage and system metadata. Raw application data never becomes diagnostics.

`finalMessageMetadata(backend:)` preserves actual final-message ID, clock, structured position and explicit turn/input lineage without adding an ID when one is absent. The current Codex, Claude Code, Pi, Hermes and local-model ordinary final producers do not forward an assistant message ID; run/turn/segment values never fill that gap. Installed OpenClaw 2026.10.2's `broadcastChatFrame` projects the actual final message, whose `id`/`messageId`/`__openclaw.id` and position can therefore be retained when supplied. This source audit is not a recorded phone final. Conflicting envelope/message lineage stays explicitly marked rather than becoming unknown absence; that final snapshot and source/media binding are rejected while the partial reply remains. Run and tool-boundary state uses original UTF-8 bytes, including canonically equivalent strings.

`terminalNotice(backend:)` validates the actual error-only system terminal message separately (bounded nonempty ID/text, no inferred timestamp). Codex's real `codexTurnFailure` supplies the same system identity to live and history; its compatibility assistant text is suppressed only when it is the exact copy, preserving an earlier partial reply and different final content. Mobile's explicit old-Codex error-without-content fallback remains visible with no source ID or invented clock. Three synthetic failure vectors execute that pure producer, compare its history output and pin the actual service wrapper; the existing native contract checker rejects drift/reduced/corrupt samples without importing the service. No Bridge/protocol changes are required. Cumulative snapshot-prefix reconciliation and missing SDK live identities remain separate work.

## Questions and consent

`pendingRequests()` returns current in-memory requests without a network call. `listPending(sessionKey:)` additionally refreshes supported read-only session lists and OpenClaw's connection-wide device/node lists. Actual typed requests, negotiated methods or successful supported lists establish capabilities; backend names alone do not. Hermes keeps its explicit `hermes.run-approval.v1` downgrade because its older list implementation can return an empty success without a resolver. OpenClaw execution requests are recovered from real events; no unimplemented pending-list method is invented.

Questions, execution approvals and connection pairing approvals remain distinct. Pi select/confirm/input/editor answers keep their wire shapes. Codex and Claude forms preserve advertised fields, labels, custom-answer and multi-select constraints; Codex does not gain Claude's multiple-selection behavior. Execution choices come from the actual request and are intersected with implemented decisions. OpenClaw also accepts its current explicit `allowedDecisions` field; conflicting choice fields reject the request, and other adapters retain their own contract. Missing choices grant no action. Device/node pairing keys include their target, so identical wire IDs do not collide. Plugin review metadata remains visible to consumers with no actionable resolver, matching the current protocol boundary.

Applications map opaque `RuntimeRequestReference` values to their own globally scoped UI IDs. A reference is valid only on its exact connection, socket and authentication revision. `RuntimeQuestion.draftKey` is a stable hash of length-prefixed backend/connection/session/request identity for local draft retention; it neither resolves a request nor belongs in diagnostics. Retain the seven-day/32-question draft policy in the host, and validate restored selections against the current fields.

For Always, call `prepareApprovalConfirmation` before presenting the confirmation, then pass its single-use token to `resolve` after the user confirms. The token expires after thirty monotonic seconds; request identity, advertised choices and expiry are checked again at dispatch. Sheet dismissal has no runtime operation. Explicit `.cancel` can interrupt the underlying task; an ACK alone does not manufacture native question completion.

Reset/delete synchronously retire reviews belonging to the exact session before the sole management RPC: old action references and Always tokens, in-flight response waits, and both stages of older list workflows. Other sessions, unscoped execution requests and connection-wide device/node pairing remain intact; absent session metadata grants no guessed ownership. Rename, archive and native copies do not imply a reset. A later ACK never applies an old consent outcome to a replacement review. Retirement publishes the changed pending snapshot without pretending the backend resolved the request.

Only the latest accepted `loadSession` head, fenced by authentication and history revision, observes actual physical identity changes. A known-to-known `sessionId` change retires the same session authority; first-known/nil IDs, pagination and the side-effect-free history/export read do not. Session routes, request keys and physical IDs compare original UTF-8 bytes. Keep old wire IDs tombstoned for that authentication. After a proven local management non-dispatch, only a new real event/list may issue a new reference for a formerly pending review; old tokens never revive and already-submitting/unknown consent writes remain retired. A destructive write with unknown outcome holds its route across metadata, lists and history; nothing automatically retries it. Physical contexts cap at 1,024 without eviction; if an observed physical change cannot safely retire bounded state, retire authentication instead. Existing wire events without physical identity cannot distinguish a never-observed old request from a new one; no invented ordinal or backend protocol change claims otherwise.

One dispatch locks each request. Unknown outcomes, malformed write replies and peer rejections remain held until an authoritative resolution or complete list removes the request. There is no automatic write retry, including after metadata changes or reconnect. New authentication clears the authority registry before any await. Lists parse fully before replacing state, reject scope mismatches/duplicates, and fence both newer reads and intervening events. The registry caps 256 requests/8 MiB and 1,024 resolution tombstones per authentication; refreshes cap two concurrent calls, eight seconds per route, 128 entries/1 MiB per response. Expiry uses both the advertised wall deadline and a captured monotonic deadline. Hermes may forward fractional milliseconds; finite nonnegative JS-safe numeric deadlines round down, never extending authority. Missing/null expiry stays absent; negative, nonfinite, unsafe and nonnumeric values remain invalid.

## Verification and limits

`ClawketRuntimeTests` uses injected sockets/monotonic time, verifies real recorded OpenClaw/Hermes contracts, and exercises authentication, bootstrap, recovery, replacement, catalog and send/history semantics. `ClawketTransportTests` separately verifies real URLSession traffic against an isolated loopback server. These checks establish native protocol behavior, not phone/Relay connectivity or successful model inference.

The runtime does not complete [the native preservation checklist](PARITY.md). Host binding and device acceptance for consent/work, attachments/artifacts, full management, voice/Node/sharing/payments/localization, legacy data import and production-backend/device acceptance remain explicitly gated work. The current mobile client remains the shipping client until those gates pass. No package distribution, service deployment or public release follows from merging this module.

Older OpenClaw closed connect schemas retain Mobile's bounded bootstrap compatibility: only the original outer `INVALID_REQUEST`/`BAD_REQUEST`, no `details.code`, a `bootstrapToken` reference and `unexpected`/`invalid connect` wording may recycle the active bootstrap handshake to a preserved token/password. Disable both configured and Relay-issued bootstrap for that activation; retain waiters across retirement, reauthenticate on a fresh transport and require actual hello readiness. Any present `details.code`, including unknown or malformed values, vetoes that legacy schema fallback. Known auth/policy detail codes produce fixed terminal categories; unknown details stay generic and never match an `AUTH_*` prefix. Other authentication/schema failures and bootstrap-only configurations never downgrade. `AuthenticationCompatibilityTests.swift` verifies direct token, Relay password, missing legacy credentials, repeated rejection and unrelated/auth errors (five tests, nine parameterized cases).

Direct Hermes authenticates at WebSocket Upgrade. When an explicit separate `auth.token` is supplied, build its encoded token query only in the ephemeral endpoint, replacing a stale URL token and preserving the credential-free stored URL. Existing embedded-token QR records still work; Relay always uses its own client token, and the other five direct backends never gain a token query. Endpoint regression includes plus-sign encoding and length limits.

`OpenClawConnectErrorTests.swift` uses sanitized envelopes from the installed OpenClaw 2026.10.2 Gateway message-handler/connect-error-details contracts, including the actual outer `INVALID_REQUEST` with nested `AUTH_TOKEN_MISMATCH` shape. It verifies direct/Relay scope isolation, preservation of shared/Node/other-connection credentials, one repair before proven readiness and structured-detail vetoes on misleading bootstrap schema prose. This is protocol evidence, not a change to Gateway policy or a successful phone authentication claim.
