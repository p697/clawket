# Native model settings

The composer’s model control opens one native settings sheet for its exact conversation. A compact current/recent/default model list leads to a searchable provider catalog; small catalogs show all rows directly. Preserve native recommendation order and alias IDs, keep featured row order stable during a review, and display backend/model names verbatim. The runtime supplies the scope, current values and actual actions. An unavailable or unknown value never becomes an invented default or an off switch.

`NativeModelControls` owns ephemeral references, host activation/wire context, read revisions and synchronous write reservations. Both the native settings sheet and legacy model-selection events enter this controller. Every receipt must match its original reference, connection, caller, scope and action; effective state remains distinct from acknowledgement. A successful acknowledgement followed by a failed read says that the setting was confirmed and needs refreshing. Unknown dispatch removes its spinner, holds the write, and never automatically retries. Fresh positive runtime state is required to reconcile it. Failed settings reads alone do not block chat or Stop.

Permission choices first prepare a real thirty-second Runtime confirmation. The host freezes that exact token/reference behind a unique presentation ID before showing the system dialog and consumes the snapshot synchronously on confirmation. Dismissal never changes permissions. Advertised permission presets can explicitly repair unknown effective permissions; this does not enable other held setting actions. Custom computer settings, unknown modes and a real confirmation requirement remain distinct.

Native setting writes reserve the actual `usesNativeSendBarrier` synchronously. Composer submission, held-message resume and queue drain recheck it after asynchronous preparation and persistence; Stop remains independent. Model writes also retire image-capability evidence until a real current-model observation, including global Hermes changes and unknown results. The final Runtime send boundary additionally checks image model holds so an actor hop cannot dispatch an image through a newly changed model. Ordinary text on OpenClaw/Hermes is not blocked merely because a model selection is pending. Existing file/image capability negotiation and bounded media ownership stay unchanged.

Legacy thinking choices prepare `/think <level>` for the existing durable outbox, with the original connection/session/scope and a new local idempotency key. They do not call a settings RPC or clear the composer/attachment draft. Queue insertion and chat acknowledgement never claim the thinking level applied; only actual controls/history metadata can do that. A persistence failure retains the local item for review and cannot trigger an automatic retry.

Recent model keys are bounded local display preferences: at most six per connection, 128 connections and a 256 KiB protected document. Unknown atomic write outcomes stop further writes from stale memory until reopening. No Runtime reference, confirmation token or wire authority is persisted. OpenClaw’s configured default badge uses a separate optional global read; failure cannot replace the concrete session’s authority or prevent free model selection.

All fixed strings use the main application’s 19-language catalog. Focused presentation contracts, controller/persistence regressions, real application compilation and compiled localization verification are separate evidence from physical-device and six-backend acceptance. This slice performs no automatic remote setting change, phone operation, service change or release.
