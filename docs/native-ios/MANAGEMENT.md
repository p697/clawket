# Native management preservation

The current Mobile client and `packages/agent-protocol/src/{capabilities,management,profile}.ts` define the preservation baseline. A backend's declared ceiling, its current negotiated refinements and the selected row's actual permission are separate checks. A successful list, readable native history or ability to copy a conversation does not authorize changing the original. Backend, transport and service environment remain distinct.

## Session lifecycle API

`sessionManagement(sessionKey:)` uses a catalog read during the current authentication and returns the descriptor, allowed actions, write state and an opaque `RuntimeSessionReference`. The reference is neither Codable nor caller-constructible. Obtain it for the selected menu/confirmation; never persist it, put it in diagnostics or rebuild it from a session key. Catalog refresh, authoritative row replacement and authentication retirement invalidate old references. At most256 references,256 held/in-flight targets and32 pending writes exist per authentication.

`renameSession`, `resetSession`, `deleteSession` and `archiveSession` consume the reference after local validation and immediately before dispatch. Their receipt identifies the captured connection/key/native session ID and exact reference, not whatever the application currently displays. The host must recheck its own selection/activation revision before changing navigation or deleting local history. An ACK does not manufacture a fresh renamed/reset row: explicitly refresh the catalog. Reset/write dispatch retires older catalog/history completions first.

OpenClaw uses `sessions.patch {key,label}`, `sessions.reset {key,reason:'reset'}` and `sessions.delete {key}`. An explicit method list grants only its listed methods, including no support for an empty list. Only when method advertisement is absent may an actual successful current-authentication `sessions.list` retain Mobile's declared historical CRUD ceiling. Malformed/present advertisement never becomes this fallback. Original row restrictions still apply, including legacy missing-row-action compatibility; main and channel sessions cannot be deleted. An unsupported-method error never changes RPC shape or retries a write. Hermes requires `hermes.multi-session.v2`, uses `{key,title}` for rename and `{key}` for reset/delete, and keeps imported native rows read-only. SDK adapters use `sessions.rename {sessionKey,title}` and `sessions.reset/delete {sessionKey}` with explicit row permissions. Codex and Pi titles are bounded to200 UTF-16 units, Claude Code to300. Active-run rules follow the actual operation: supported renames remain available; SDK reset/delete and Codex archive wait for idle. The backend still validates current native ownership at dispatch.

Codex archive requires exact `health.sessionArchive === true` plus `allowedActions.archive`. `listArchivedSessions()` reads and validates the separate archived list, including the actual native projection that omits `hasActiveRun`; this omission is accepted only on that route. Archived rows offer restoration, not rename/reset/delete. When archive is offered, permanent delete stays hidden as in Mobile. `sessions.archive {sessionKey,archived}` never grants original-thread continuation; read back fresh state afterward.

`branchSession(reference:title:)` is separate from original-session writes. Codex/Claude Code/Pi require the declared branch feature, a current `source:native` read-only row and an available inherited project. It sends `sessions.create {fromSession,title?}` without an arbitrary project/path override, validates a different owned result and leaves the original intact. Claude's desktop `in_use`/`ownership_unknown` rows may be copied; `project_unavailable` cannot. Codex's active source cannot be copied. Known native original input requires current catalog evidence and exact `canContinue:true`; Hermes native input remains read-only. Unknown/created owned keys retain the backend's final enforcement, with no key-shape inference.

No write is replayed. A proven local non-dispatch permits a newly obtained explicit action; an uncertain or malformed response holds that target for the current authentication, including across catalog refreshes. New authentication removes old authority, never resends an old request and cannot let a late receipt mutate the replacement. This runtime verification does not complete host menus/confirmations or device acceptance.

## Remaining management slices

| Surface | Current source / wire oracle | Preservation boundary |
|---|---|---|
| Agent identity | `AgentSettings/IdentityScreen`; OpenClaw `agents.list/create/update/delete`, `agents.files.get/set` | Name/emoji are Agent records; vibe merges existing IDENTITY.md; avatar remains desktop-owned. Hermes has no identity writes. Codex/Claude names are local connection labels. |
| Memory and skill documents | `FilesSection`, `DocumentScreen`, `document-model`; `agents.files.list/get/set`, `skills.get/content.update` | Backend-returned file names/opaque handles only; missing-file creation, dirty edits and existing Pro gates; linked skill files read-only. Local document versions/diff/restore/clear are user content. |
| Installed/discovered skills | `SkillsSection`, `SkillDiscoverScreen`, `Thread/components/SkillPickerSheet`; `skills.status/update/delete`, SDK `skills.list` | Actual availability, requirements, enable/delete rights and session context. Selection/install discovery prepares a draft; negotiated Hermes source-pinned `skills.install` is a distinct explicit operation. |
| Scheduling | `CronSection`, `CronEditorScreen`, `cron-model`, `cron-run-content.adapter.test` | OpenClaw `cron.*`, config-backed heartbeat/`last-heartbeat`; Hermes `hermes.cron.jobs.*` and `.outputs.*`. Preserve Agent filtering, runs/output identity, model namespaces, delivery/timezone metadata and system-owned job restrictions; refinements require negotiation. |
| Models | `ModelsScreen`, `model-catalog`, OpenClaw adapter catalog helpers | Global vs session selection, thinking, native speed/permissions, fallback order, allowlist, provider/add/delete/reference analysis and cost overrides. OpenClaw config writes require a fresh hash; Hermes stays global and negotiates model health. |
| Usage | `UsageSection`, `UsagePosterSheet`; `sessions.usage`, `usage.cost` | Agent owner/timezone/date range, explicit unknown/included/estimated pricing, local save/share poster. Codex quota is separate profile data. |
| Codex profile v1 | `NativeProfileScreen`, `profile-reply`; `profile.defaults/usage/skills/instructions/document/mcp/plugins` | Exact version1 negotiation, versioned defaults/documents, authorized project IDs and skill toggles; MCP/plugins read-only. Never generalize to arbitrary filesystem paths. |
| OpenClaw config/tools/channels | `OpenClawManageScreen`, `ToolsSection`, `ChannelsDevicesSection` | `config.get/patch/set` with baseHash/explicit replacePaths, `tools.catalog`, `channels.status`, scoped tool/DM/account config patches. Channel deletion stays outside the app. |
| Permissions/diagnostics | `gateway-client.ts:requestPermissions/requestDoctor/requestDoctorFix` | Relay control request/result/error frames, not invented Gateway RPCs; bounded reads and explicitly confirmed repair. Keep separate from SDK per-session permissions and execution consent. |
| Backups and logs | OpenClaw adapter config backup helpers; `DocumentHistorySheet`; `LogsSection` | Phone-local config restore points vs document versions; restore reads a fresh config hash, remove may be local/offline. `logs.tail` is bounded/cursor based; raw user-visible logs never become telemetry. |
| Devices and Nodes | `ChannelsDevicesSection`; `device.pair.*`, `node.list/rename`, `node.pair.*` | Paired-device management differs from pending consent and phone-as-Node. Exact native IDs and pending request IDs cannot substitute for each other. |
| Phone as Node | `services/node-client`, `node-capabilities`, dispatcher/handlers; `App.tsx` sidecar | Separate role=node handshake/token scope and implemented device/status/notify/camera/photos/location/clipboard/media handlers. Persisted enable state exists although current settings have no visible toggle consumer. Advertise only implemented native commands. |
| Bridge update | `BridgeUpgrade`, `bridge-update` contract | Positive Bridge capability and distinct OpenClaw Relay controls vs SDK RPC; a code merge does not authorize release/update actions. |

The broad management groups belong to OpenClaw; Hermes supports its own files/skills/cron/usage but no Gateway config/tools/channels/devices/Nodes/logs. Codex supports its negotiated profile and session controls; Claude Code/Pi keep their narrower session/model/skill contracts. Local-model has one main chat and global models, with no session management. Each slice must carry both source-backed wire tests and stale-generation/unknown-write tests.
