# Native work and review cache

The real app binds `RuntimeSessionUpdate.work`, typed history work, actual run starts/finals and captured send receipts to `NativeTaskJournal`. The optional work dock opens the native inspector with selectable bounded input/output. Inspection validates the exact conversation, dock, record and step identities; it performs no network write. Opening, updating and closing it do not change composer ownership, focus or transcript scroll requests.

## Identity and status

Each cached run and step has an independent persistent UUID for rendering. Connection/Agent/session scope is explicit. A producer run, turn, input-message ID or input-message key can join only a unique nonconflicting record. Reusing a run with another known input creates a distinct record; a partial final matching multiple records mutates none. A reused run start and new tools without input identity remain in an explicitly unattributed bucket; a later receipt cannot retroactively assign that bucket to another known input. A history tool without execution lineage stays an unattributed history record with its exact source-message/block identity. It is not assigned to a nearby prompt by prose, command or time. A history item with actual matching lineage/tool identity updates the existing live record and retains its render ID. Earlier pages insert new records/steps before existing ones while retaining established run order. Head history uses its canonical sequence and preserves unmatched work actually observed live after it; clocks never supply order.

Commentary is one cumulative item, separate from assistant message segments. Tool inputs, outputs, names, explicit statuses and producer clocks are preserved at the adapter boundary. Gateway's actual terminal `result` phase retains its existing success/error semantics; arbitrary output or an unknown phase does not prove success. A run final may finish that exact run, but cannot mark unresolved tools successful. Unknown stop reasons remain unknown. Producer dates/durations are retained verbatim, including clock skew; they never manufacture state. Phone-observed start/end/monotonic duration stays separate and is not shown as a backend duration. Cold recovery and lost readiness mark nonterminal records unknown without restarting a timer or task.

Typed history projection preserves multiple embedded tool calls/results and ordinary tool rows. Malformed optional items do not suppress the usable transcript. Full assistant segment/live-history reconciliation, imported CLI rollups, turn compaction/reset handling and device reading-anchor acceptance remain pending; this cache does not claim those broader parity gates are complete.

Shared SDK `role: tool` rows store their metadata in a nested `tool` object. Read its actual `callId`, name, status, summary, input/output and clocks while retaining Gateway's top-level result shape. A clock/output without status never proves success. The checked `ClawketRuntimeTests/Fixtures/sdk-history.json` is generated from synthetic inputs through the actual Codex, Claude Code and Pi Bridge history functions (`node tests/native-contract/sdk-history.mjs --write`). Required Node checks compare the current producer output/source digests and reject empty, corrupt or reduced vectors; Swift consumes the same eight tool rows. These are protocol-contract tests, separate from real SDK phone acceptance.

Conversation display filters only empty/whitespace tool rows without attachments, after the typed work reducer has consumed history. Original cached messages and raw work remain intact; text-bearing and media-bearing tools stay visible. Title fallbacks compare exact known protocol IDs rather than guessing from UUID shapes; explicit backend names remain verbatim, and derived human-message/preview snippets are display-only and bounded to 160 whole characters and 4 KiB (an oversized grapheme falls through safely).

## Persistence and bounds

One dedicated protected `NativeTaskJournal` directory stores `tasks.v1` plus a verified rollback. The primary document is at most 8 MiB, with at most 128 runs, 4,096 total steps, 1,024 steps in a run and 32 reviews. Each raw input/output retains up to 256 KiB; larger or deeply nested values become an explicitly incomplete UTF-8-safe serialized preview. Missing producer completeness also remains conservative. Text detail is bounded separately. Aggregate JSON bytes, nesting, tokens, identities, orders, scopes and question-response semantics are validated before persistence and again before recursive decode. Eviction affects this review cache, never the separate composer/outbox, saved conversations or question-draft store.

The store serializes transactions across actor suspension and rejects older or duplicate revisions. Read-back verifies writes. A malformed primary, including domain-invalid JSON, may recover only from an independently validated rollback; neither invalid copy is rewritten during recovery. Unreadable storage does not become an empty writable journal. A failed or unknown commit disables further journal writes until reopening, while connection/text functionality remains usable.

The cache contains local application content, not telemetry. It stores no `RuntimeRequestReference`, available decisions, confirmation token, socket authority or serialized action. Approval/question correlation hashes match display copies only. Cold review cards use independent journal IDs and cannot edit, submit, cancel or approve. Only a freshly observed Runtime request can replace the inert card with current authority. Resolved answers are labeled accepted only for an exact local answer/confirmation followed by authoritative acceptance; cancellation, expiry and external resolution keep retained values labeled as drafts. Explicit false and accepted empty answers survive encoding.

## Evidence

`WorkHistoryTests.swift` covers start lineage, actual Gateway phases/raw values, embedded history, exact clocks, optional malformed records and completion metadata. `NativeTaskJournalTests.swift` adds 12 actual app regressions for ambiguous lineage, stable item IDs, cumulative commentary, late starts, unknown status, UTF-8/depth bounds, revision ordering, verified rollback/corruption, cold recovery, inert receipts, accepted-answer validation and aggregate eviction. Four additional `NativeTaskRequestsTests` cover own/external/cancelled answers and cold review replacement. The actual app test-count floor is 44 before later independently added suites.

Strict Swift 6 generic Simulator development compilation verified the first actual host and its 44 test methods without starting a local simulator. A subsequent independent review added counter-overflow, reused-run attribution, older-page ordering and local-acknowledgement safeguards; final source compilation and execution remain CI gates. Actual app test execution and the complete repository gates run in CI. Real backend tools/approvals, cold receipt inspection, USB/iPad/VoiceOver and reading-anchor/IME acceptance remain separate tests; no distribution or production change is implied.
