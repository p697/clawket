# Native Pro and purchase ownership

This belongs to the independent native iOS experiment. React Native remains the default supported client; code/CI completion does not accept the native UI, authorize a switch or prove real store purchase/account behavior.

The iOS host uses RevenueCat's public Swift SDK **5.94.0**, pinned exactly in the Xcode project and its resolved file. `ClawketCommerce` stays independent of that SDK: it owns access policy, the protected free-slot/grace record, offering selection and explicit purchase coordination. The host adapter alone holds current SDK package references and converts real customer information. The current Mobile consumers (`pro.ts`, `pro-entitlement-storage.ts`, `pro-subscription.ts`, `manual-sessions.ts` and `session-preview.ts`) are the compatibility source.

## Identity and configuration

The development bundle remains `com.p697.clawket.nativeqa`. Its own SDK defaults create or reuse its own anonymous purchase identity. No login, logout, alias, device-ID account or automatic restore is performed. The store bundle remains blocked by `NativeVault` until the same-bundle importer is fully integrated. Its purchase identity resolver accepts only a validated Upgrade result, preferring the preserved current RevenueCat user ID over the legacy ID. A missing old identity is not permission to generate a replacement purchase account. QA never receives that imported ID.

These public build settings are empty in the community project: `CLAWKET_REVENUECAT_IOS_API_KEY`, `CLAWKET_REVENUECAT_ENTITLEMENT_ID`, `CLAWKET_REVENUECAT_OFFERING_ID`, `CLAWKET_REVENUECAT_PACKAGE_ID`, `CLAWKET_PRIVACY_POLICY_URL` and `CLAWKET_TERMS_OF_USE_URL`. Supply explicit Xcode build-setting overrides in the development build invocation; do not commit operator values. An Apple key starts with `appl_`; a `test_` key is accepted only by Debug configuration. Exact public URLs and IDs are configuration, never embedded maintainer credentials.

With no purchase integration requested, community access remains open, matching Mobile; it never claims paid membership and cannot buy. Partially configured or malformed store settings fail closed instead of switching to community access. Real HTTPS Terms and Privacy links are required before checkout. Prices, periods and product references come from the selected live offering; no historical dollar price or placeholder product may enable a purchase.

## Access and local ownership

Paid access comes only from the current SDK identity's active, verified or verified-on-device customer evidence and its real expiry. The application never persists a paid boolean or deserializes an app cache into entitlement authority. Failed refreshes preserve still-valid verified evidence but cannot extend its deadline. Customer expiry and the one-time grace deadline keep ticking independently of refresh success, including a multi-day expiry after an intermediate offline read.

The secure device-scoped allowance preserves Mobile's version-1 schema: explicit nullable `freeConnectionId`, `lastFreeConnectionSwitchAt`, `graceUntil`, and a once-only `graceEvaluatedAt`. A free slot may change once every 24 hours. Only validated legacy usage can establish the old fourteen-day connection/Agent grace; a fresh install, paid bootstrap, corrupt record or reinstall cannot renew it. Grace never grants adding another connection, Agent creation or other Pro features. Exact UTF-8 IDs distinguish canonically equivalent display strings. An unknown protected replacement stops further writes until verified cold recovery.

The complete provider decision set replaces the roster's historical registry fallback, including an explicitly empty set on setup failure. An actual default-Agent flag is required; names and main-session spelling do not identify a free Agent. The host rechecks current decisions after asynchronous preparation and immediately before its dispatch call, together with the physical-history operation and current-epoch gates. Remote complete-export reads also require that current physical scope. Complete-export sharing keeps its original request and rechecks it before and after file preparation, releasing an unpresented copy if access or scope changes. Local saved/physical single-copy sharing remains independent. Expiry holds undispatched local outbox items with original text, resources and idempotency keys. Purchase success does not replay them; Stop remains independent.

Full session reading follows the actual Mobile exceptions: a real main descriptor (with its bounded legacy fallback), a Bridge-owned sessions-first row, or an exact persisted create receipt. Titles and native source kinds cannot mint a manual record. The independent manual-receipt store caps at 1,000 entries and persists a real returned create result before publishing that free-session exception. Unknown persistence cannot authorize a second backend create.

Other sessions show a frozen two-body read-only preview plus current runtime reviews. Native additionally keeps the user's own held/failed/uncertain outbox visible so expiry cannot hide editable ownership. Preview state resets at the actual physical epoch/open generation; it never restores dispatch authority. Saved search and bulk export use the same live provider, revalidate after awaited reads/preparation, and retire unpresented export work on access loss. Saved/physical copies still remain readable without becoming live wire authority.

## Explicit store operations

The custom native paywall uses the existing companion vector, the Mobile silver visual language, Dynamic Type and Reduce Motion. It advertises the native capabilities actually implemented: connections/Agents, full conversation history, saved search and bulk export. Annual, lifetime and monthly options use real StoreKit formatted prices, the actual monthly equivalent and renewal disclosure. Owned lifetime and grandfathered pre-2026-04-18 annual membership cannot be repurchased; current plans, foreign-store subscriptions, family sharing and unknown recurring plans keep their existing change restrictions.

Each checkout refreshes customer evidence first and synchronously reserves one operation before awaiting. Cancellation stays quiet. Pending/unknown payment, a scheduled recurring change and a presentation-only redemption never count as newly activated entitlement or replay checkout. Lifetime purchase does not cancel an existing renewing subscription and directs the owner to the system management surface. Restore and code redemption are explicit actions. Redemption uses Apple's native sheet, never collects a code, and performs at most twelve five-second foreground reads; closing retires that continuation.

A genuine success may update global access even if its old view closes. Refreshing or foregrounding a result view preserves its pending/scheduled/success state and cannot re-enable checkout. Continuing the prior action requires the same review, presenter, route, activation, wire, selection and physical epoch, followed by the actual paywall dismissal callback and a current access check. A later view cannot adopt it. StoreKit receipts, transaction IDs, customer IDs and native error text are not diagnostics; SDK logging is suppressed.

## Verification and remaining acceptance

Deterministic package tests use fake purchase sources, clocks and bounded protected stores; host tests use local synthetic records and never configure a real purchase SDK. Actual Sandbox purchase/cancellation/pending/restore/plan-change/redemption, real offering prices and membership after cold start remain an owner-account acceptance checkpoint. The same-bundle store identity/entitlement upgrade remains a separate checkpoint; community compilation or QA identity tests cannot establish it. This work does not authorize a payment, store configuration change, distribution archive, upload or release.
