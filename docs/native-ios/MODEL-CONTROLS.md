# Native model and runtime controls

The preservation oracle is Mobile's `useChatModelPicker`, `runtime-settings-status`, the six `connection/adapters` and `packages/agent-protocol/src/{management,capabilities}.ts`. Bridge's Codex `modelSelection/sessionModels`, Claude Code/Pi models methods and Hermes `model.get/model.set` provide the native response shapes. This slice implements runtime contracts; host forms and physical-device acceptance remain separate. Provider management, allowlists, fallbacks and cost overrides remain in [the management inventory](MANAGEMENT.md).

`modelControls(sessionKey:)` returns bounded catalog/effective metadata and an opaque, non-Codable reference. SDK reads without a session are catalog-only: they do not select a synthetic main conversation. The DTO always captures the caller's real route, even when the setting is global. References capture authentication/socket generation, settings revision and native session identity/ownership. Fresh reads, writes and route retirement invalidate old references. Never persist or log them. Two concurrent reads,32 references/16 MiB catalog state,128 unresolved contexts and32 pending writes are the limits; an unresolved permission requirement is never evicted to admit another scope.

OpenClaw's present method advertisement, including an explicit empty/malformed list, cannot fall back to undeclared writes. With advertisement absent, an actual successful current-authentication controls read preserves Mobile's existing model-setting ceiling. Unknown-method responses never select another RPC or replay. Native SDK settings preserve current active-run/project/continuation restrictions and final backend ownership checks; a readable or copyable original grants no setting authority.

Session thinking options take precedence over selected-model reasoning metadata, followed by the adapter's existing static command choices. Missing current/native-default metadata stays unknown. Codex/Claude preserve native catalog order and alias IDs; `resolvedModel` is display/matching evidence, not a replacement write ID. Unnegotiated speed/permission metadata grants nothing. Known permission mode, custom mode and unknown/null mode remain distinct. Missing `availableModes` retains the legacy three presets; explicit empty permits none. `unencryptedTransport` is calculated from the actual client endpoint, never accepted from the peer.

`selectModel(reference:modelID:provider:)`, `setThinkingLevel` and `setFastMode` validate current choices before consuming authority. Permissions use `preparePermissions(reference:mode:)` and a single-use thirty-second `RuntimeModelPermissionConfirmation`; the host freezes it in the native dialog and only an explicit confirmation calls `setPermissions(confirmation:)`. Dismissal is inert. The old `selectModel(id:provider:sessionKey:)` enters the same write state and invalidates opaque references, so it cannot bypass pending settings or native ownership. Claude/Pi/local-model selection retains190 seconds; other selection and Codex native setting writes retain45 seconds, separately from connection/handshake budgets. Claude catalog reads retain60 seconds.

`RuntimeModelControlReceipt` distinguishes an ACK from a parsed effective state. `state == nil` means an explicit fresh read is needed; it never fabricates the requested setting as current. Unknown dispatch stays held, is not replayed and cannot be cleared by a stale read or a retired callback. Permission requirements survive missing flags, unrelated fast/model writes and reconnection; only actual verified `requiresConfirmation:false` can clear a real requirement. A general interrupted native setting can reconcile from a real known permission projection, matching Mobile's older-peer compatibility. A model-only event received before an ACK does not discard that ACK. A model/provider change during a read retains independent permission evidence but makes old model-specific speed/reasoning availability unknown until refreshed; physical session or authority replacement retires authority. Session mutations retire same-route controls and older thinking observations before dispatch, without clearing unresolved holds.

`canSend` and `modelSendBarrier(sessionKey:)` describe only actual native setting/permission barriers. A failed catalog/settings read alone never blocks chat or Stop. `usesNativeSendBarrier` allows a host to reserve that same native barrier synchronously before its task hop, without guessing from backend names. Stop remains independent. `prepareThinkingCommand` returns only the exact connection/session route and `/think <level>` for the ordinary persisted outbox, with no direct RPC, send, retry authority or claimed application. Current Mobile adds no separate prompt `thinkingLevel` on this command path. `RuntimeHistory.thinkingLevel` preserves actual known top-level history metadata; only the latest initiated non-older head for that settings scope, with current authentication/settings revision, may feed the controls fallback. Text, command preparation, queue insertion and chat ACK never prove the setting applied.

Tests use sanitized current-producer response shapes and injectable sockets/clocks, covering all six scopes, malformed metadata, real permission requirements, confirmations, missing legacy flags,190-second waits, ACK ordering, stale reads, reset, same-ID reauthentication and bounded retention. These are local protocol/recovery evidence; they do not claim phone, Relay or model-inference acceptance.
