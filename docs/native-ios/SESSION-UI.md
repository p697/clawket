# Native conversation management

The conversation menu and each session row can open a system sheet for the selected conversation. The host obtains `RuntimeSessionManagement` at that moment, rather than issuing references for the entire catalog. Unsupported entry points remain hidden. A readable native conversation does not grant permission to change its original; the sheet shows only the runtime's actual actions.

Rename uses a separate native editor and validates trimmed UTF-8/UTF-16 limits without truncating composed text. Reset and delete require a host-owned frozen confirmation; the unique confirmation ID maps to the captured action/reference. Confirm consumes that snapshot synchronously before starting asynchronous work. Dismissing the sheet, editor or dialog never mutates the backend. Archive and restore remain distinct from permanent deletion. Archived rows open their action review instead of mounting a chat. Copying a native conversation creates a different owned conversation with its inherited project; no project override or native takeover is added.

`NativeSessionManagement` owns ephemeral references and host activation/wire/selection snapshots. An action reserves its exact target synchronously, keeps the pressed action visible while submitting, and validates the acknowledgement against the original reference, connection, logical key and physical session ID. Late results cannot navigate a replacement after leaving and returning. Read or metadata replacement retires an open menu instead of retargeting its authority.

An acknowledged write still needs a new catalog read before display effects. Runtime cancels catalog work that started while the mutation was pending, so the post-ACK refresh cannot join a pre-ACK read. An arbitrary roster event cannot unlock a deferred change; explicit recovery starts its own read with the captured operation ID. Unknown writes stay locked for the authentication and never replay. Proven local preparation failure does not enter the wire path.

The host exposes `NativeSessionMutationTarget` and `NativeSessionMutationOutcome` callbacks with original session lineage. Before reset/delete/archive, it holds queued messages and saves that change while preserving the draft, message identities and other content. Sending, queue drain and competing history reads pause during mutation. Neither an ACK nor a catalog refresh deletes the local conversation or work journal. Physical-session reconciliation and reset history boundaries remain a separate transcript integration; raw cached content is retained until that integration proves its scope.

All fixed labels and failure states are included in the real 19-language catalog. Source, focused protocol/presentation/host tests, compiled resources and actual App CI are separate evidence from device acceptance. This slice performs no phone operation, service change, release or automatic remote write.

Local verification passed serially under the shared leases: seven runtime recovery tests (eleven parameter inputs), three presentation tests, sixteen actual iOS 16.4 UI sources, and a generic Simulator build-for-testing for both architectures including thirteen new host regression methods. All 5,662 compiled localization values match the 19-language source catalogs. App test execution and the complete repository gates run in CI; no local simulator was booted. Device and six-backend management acceptance remain pending.

Physical host reconciliation now consumes each prepared reset/delete target once, independently of the post-ACK catalog result. Its local UUID is not a producer session ID. The protected unconfirmed intent is written before dispatch; unknown outcomes and connection changes hold it without replay. ACK archives the exact previous working record before adopting a replacement, preserves current composer/files, and holds retained inputs in their original epoch. Catalog-only archive/restore/rename/branch operations do not invent physical resets.
