# Native transcript reconciliation

The shipping host applies `NativeHistoryApplication` after a current Runtime read. `NativeHistoryIdentity` accepts only a unique actual producer ID or actual structured transcript position, with compatible role and original UTF-8 author/account/channel identity. A unique idempotency key can acknowledge an already-owned direct user send. Duplicate IDs, conflicting keys, two echoes consuming one row, participant changes and wire `sentLocally` flags never grant ownership. Synthetic IDs, hashes, text, clocks, run IDs and inferred paragraph numbers are not message identities. Legacy caches decode missing provenance as unknown.

`NativeLiveMessages` consumes actual text/final events after host routing. It receives the current epoch explicitly and assigns independent render UUIDs, matching only a unique active run/segment pair by UTF-8 bytes. Delimiter aliases, canonical Unicode aliases and prior epochs cannot overwrite another row. Final metadata and attachments bind to that exact segment, with conflicting known source/participant/input evidence rejected; image-only finals also receive a UUID. Duplicate source IDs remain visible and ambiguous. Explicit turn/input fields survive caching, while absent legacy fields stay unknown. Source-content hashes remain pixel freshness checks only.

For a complete `chat.message` snapshot with an actual message ID, the reducer also checks a unique source candidate. It may bind an existing live segment or an explicitly active history row only when source and segment candidates agree, role/epoch and known producer lineage remain compatible, and no permanent ambiguity exists. The render UUID stays unchanged. History-first eligibility requires actual current-head activity plus the row's actual run ID matching `activeRunID`; source identity alone cannot make a cached row active. Only an actual accepted current-wire snapshot promotes `historyActive` to live `active` and owns the cumulative body. Every legitimately selected final assistant target receives a local terminal marker, including history-only, image-only and legacy segment targets; old caches decode that marker as unknown. True delta fragments never use a history-hydrated body as their append base. Active or unknown heads preserve the accepted live body, including after final completion. A terminal row with an actual segment retains its complete content and media without an accepted incoming index until a confirmed terminal head may adopt the final history body. Only accepted incoming indices hydrate media/work.

The document also carries up to 128 byte-exact ambiguous source IDs scoped to its physical epoch. Duplicate/previously ambiguous source IDs and explicitly contradictory same-source provenance remain inert across a later unique head, empty head and cold restore; every retained copy remains marked ambiguous. Both history and live/final observations can establish that negative evidence. A typed text reduction distinguishes accepted text, changed ambiguity memory and complete rejection: the host must save changed negative evidence without granting text acceptance, journal text, run activity or streaming proof. Terminal/unknown activity alone, display segment disagreement and internally conflicting incoming metadata do not create source contradictions. Capacity overflow disables source joins rather than evicting an old failure to grant new authority. Corrupt or oversized cached memory fails closed. A different physical epoch starts a separate memory. These are local reconciliation constraints, never backend identity, transport readiness, outbox ownership or RPC credentials.

Independent `retiredTerminalSources` remembers actual terminal assistant source IDs only when an accepted head removes their rows. It preserves original UTF-8 bytes across an empty head and cold restore; a reappearing source stays terminal and a direct late snapshot cannot create a new live row. This local negative evidence does not assert cloud state or mark the source ambiguous. Rows still present need no additional entry. The memory keeps at most 4,096 IDs and 256 KiB of ID bytes per epoch, without eviction. A head that would exceed either bound fails explicitly before publication or media retirement, preserving the prior cache. It does not globally reject new-source text already admitted by a ready host. If the first cold-start head fails, physical readiness remains unavailable and live/send stays blocked until the existing recovery/new-session path succeeds; a reducer-only fresh-source test is not proof of writable cold recovery.

This handoff covers only actual source-backed complete snapshots. Current OpenClaw ordinary deltas and Hermes live frames omit the needed ID; Codex/Claude aggregate multiple items, Pi may emit several messages per run, and local-model history names do not establish a new live ID. Those paths keep the conservative behavior and can retain a temporary duplicate until authoritative history converges. No run/content guess, producer rewrite or six-backend de-duplication claim is made.

Live/final compatibility retains the existing conservative full-attribution comparison. A display-name/avatar-only change may reject a source-backed snapshot until a later authoritative head updates that metadata; it does not establish a permanent source contradiction unless actual participant identifiers disagree. This slice does not claim support for every producer metadata update.

An actual system terminal notice has its own row and supplied source ID; it does not replace partial assistant text or manufacture an assistant ID. The existing Codex legacy fallback has neither source ID nor a guessed clock. Only the five fixed Mobile system-failure notices are localized at presentation across the same 19 locales; original text stays in the cache, and user/assistant/arbitrary backend prose remains verbatim. Real live-to-history source joining is available only where the producer supplies evidence; ordinary SDK assistant finals still lack that evidence.

The actual host adopts negative-only text reductions through the same post-physical-gate handler as accepted text and saves their document revision. Only accepted text advances the live revision, journal text, current running state and display stream proof. Current-head activity uses strict three-state evidence: unknown preserves an observed run and queued inputs, explicit false may end it, and true may recover activity. Earlier pages and heads captured before a newer accepted live revision cannot replace running state; only a validated actual run ID can enter physical live evidence.

Actual retained run-finished journal evidence also constrains start/text adoption and history activity/admission, including after cold restore. Require the exact current route, nonnil epoch and UTF-8 run ID, a retained actual terminal fact and compatible known turn/input lineage across matching records. A late-work display bucket with only the run ID cannot erase that fact; actual conflicting input lineage remains unknown. Source/item completion never proves that a multi-message run ended. This reuses the existing bounded journal (128 runs, 4,096 steps and byte limits); trimmed or legacy facts remain unknown. It is not an unlimited run tombstone ledger. Late work, consent and final-media consumers retain their existing gates.

Rows have independent persistent render UUIDs. Head reads preserve API order, concurrent live/edited rows and owned outbox values. A partial head retains an older prefix only with ordered exact anchors; cursor pages weave around those anchors and reject reversed order. A full message snapshot, activation, socket readiness and per-route read generation fence late reads. Older pages cannot clear the current run. No timestamp sort or first matching ambiguous ID is used.

The accepted incoming-index → render-ID map is the only history input to work reduction and attachment hydration. Work fallback anchors use that render ID while actual tool/run/turn/input IDs stay unchanged. Stale rows and overlapping earlier-page rows cannot inject older tool output. Duplicate producer IDs therefore cannot choose another row's attachment or synthetic work item.

An exact sorted raw-content SHA-256 checks cached inline media freshness only. Changed bytes retire cached pixels and the old load token even when the producer ID is unchanged. Attachment references include the persistent render UUID. Release intents are durably journaled before a document without the old resource can be published; a concurrent change aborts that read. Current/rollback references still protect files during reclamation. A proven local echo keeps its original input files despite backend re-encoding or omission.

The UI distinguishes owned sends, unattributed direct-chat user history, explicit participants, Agents and system/tool rows. Direct history uses outgoing layout without queue actions or delivery claims. Participant names/handles remain verbatim, unknown names have a localized fallback, and a real participant context labels the Agent. Valid producer timestamps use the phone's locale/time zone; absent/invalid clocks do not invent a current time. Titles compare exact protocol bytes before choosing human-readable fallbacks.

Assistant Markdown renders fenced code through the existing native code card, with its supplied language, selectable literal text and independent 44-point Copy control. Copy pauses following and copies the exact block body, including CRLF, indentation and Unicode spelling. The parser recognizes backtick/tilde fences of at least three matching markers with up to three leading spaces and a whitespace-only closing tail ([fence rules](https://spec.commonmark.org/0.31.2/#fenced-code-blocks)); it does not rewrite nested list/blockquote structure or dedent the original code. Other prose retains its existing inline Markdown formatting. Opening fence tails stay literal until a line ending; complete matching closing fences also close at EOF. Short or invalid closing tails remain literal code. These rules depend only on raw text, so losing streaming proof on disconnect cannot reinterpret unchanged content. An opened, unclosed block shows its available body without inventing a closing fence or completion status. View keys use original UTF-8 offsets within the original content index, not new message IDs, hashes or protocol metadata. Markdown/code equality and hashing preserve byte differences so corrected code refreshes its Copy payload. User, system, tool and attachment projection remain separate.

Only the actual tool role maps to `MessageContent.toolOutput`. Its native disclosure starts collapsed; expanding exposes the complete verbatim text with TextKit selection and a real 44-point native Copy control. Monospaced formatting preserves Markdown punctuation and line breaks rather than interpreting tool output as a new assistant answer. The existing localized Tool output label makes no name, status or completion claim, and raw JSON is never parsed for those claims. Attachments remain independent content. Expansion belongs to the existing presentation state and invokes the same reading-interaction callback; it changes no stored text, work lineage or remote authority.

The transcript projection suppresses an assistant row only when its text is whitespace-only, it has no media and it is no longer streaming. Empty active responses and media-only responses stay visible. The previous empty-tool suppression remains separate. All original rows remain in cached history and the work journal, so presentation cleanup cannot erase a receipt or hide an attachment from recovery/export.

The UIKit transcript observes published reading scopes directly. Its coordinator captures the actual first visible row synchronously from the main-actor appearance publisher before message rows receive a new font. This differs from the requested restoration row, whose partially visible predecessor may be the reader's actual anchor. Offscreen targets are materialized before bounded layout/offset corrections; ordinary captures cannot replace a requested anchor with transient estimated geometry. Unchanged offsets do not schedule another scroll.

Physical-session rollover and legacy transcript archival are a separate host integration. The optional message epoch is preserved metadata; this slice does not invent a physical epoch from a logical route or reset text. Reset/compaction markers and actual session IDs are retained, but cannot by themselves claim complete history acceptance. Live-to-history joining also requires actual producer evidence; run/turn/segment IDs are not guessed into message IDs. These items and actual six-backend/device acceptance remain pending in `PARITY.md`.
