# Native transcript reconciliation

The shipping host applies `NativeHistoryApplication` after a current Runtime read. `NativeHistoryIdentity` accepts only a unique actual producer ID or actual structured transcript position, with compatible role and original UTF-8 author/account/channel identity. A unique idempotency key can acknowledge an already-owned direct user send. Duplicate IDs, conflicting keys, two echoes consuming one row, participant changes and wire `sentLocally` flags never grant ownership. Synthetic IDs, hashes, text, clocks, run IDs and inferred paragraph numbers are not message identities. Legacy caches decode missing provenance as unknown.

`NativeLiveMessages` consumes actual text/final events after host routing. It receives the current epoch explicitly and assigns independent render UUIDs, matching only a unique active run/segment pair by UTF-8 bytes. Delimiter aliases, canonical Unicode aliases and prior epochs cannot overwrite another row. Final metadata and attachments bind to that exact segment, with conflicting known source/participant/input evidence rejected; image-only finals also receive a UUID. Duplicate source IDs remain visible and ambiguous. Explicit turn/input fields survive caching, while absent legacy fields stay unknown. Source-content hashes remain pixel freshness checks only.

An actual system terminal notice has its own row and supplied source ID; it does not replace partial assistant text or manufacture an assistant ID. The existing Codex legacy fallback has neither source ID nor a guessed clock. Only the five fixed Mobile system-failure notices are localized at presentation across the same 19 locales; original text stays in the cache, and user/assistant/arbitrary backend prose remains verbatim. Real live-to-history source joining is available only where the producer supplies evidence; ordinary SDK assistant finals still lack that evidence.

Rows have independent persistent render UUIDs. Head reads preserve API order, concurrent live/edited rows and owned outbox values. A partial head retains an older prefix only with ordered exact anchors; cursor pages weave around those anchors and reject reversed order. A full message snapshot, activation, socket readiness and per-route read generation fence late reads. Older pages cannot clear the current run. No timestamp sort or first matching ambiguous ID is used.

The accepted incoming-index → render-ID map is the only history input to work reduction and attachment hydration. Work fallback anchors use that render ID while actual tool/run/turn/input IDs stay unchanged. Stale rows and overlapping earlier-page rows cannot inject older tool output. Duplicate producer IDs therefore cannot choose another row's attachment or synthetic work item.

An exact sorted raw-content SHA-256 checks cached inline media freshness only. Changed bytes retire cached pixels and the old load token even when the producer ID is unchanged. Attachment references include the persistent render UUID. Release intents are durably journaled before a document without the old resource can be published; a concurrent change aborts that read. Current/rollback references still protect files during reclamation. A proven local echo keeps its original input files despite backend re-encoding or omission.

The UI distinguishes owned sends, unattributed direct-chat user history, explicit participants, Agents and system/tool rows. Direct history uses outgoing layout without queue actions or delivery claims. Participant names/handles remain verbatim, unknown names have a localized fallback, and a real participant context labels the Agent. Valid producer timestamps use the phone's locale/time zone; absent/invalid clocks do not invent a current time. Titles compare exact protocol bytes before choosing human-readable fallbacks.

Only the actual tool role maps to `MessageContent.toolOutput`. Its native disclosure starts collapsed; expanding exposes the complete verbatim text with TextKit selection and a real 44-point native Copy control. Monospaced formatting preserves Markdown punctuation and line breaks rather than interpreting tool output as a new assistant answer. The existing localized Tool output label makes no name, status or completion claim, and raw JSON is never parsed for those claims. Attachments remain independent content. Expansion belongs to the existing presentation state and invokes the same reading-interaction callback; it changes no stored text, work lineage or remote authority.

The transcript projection suppresses an assistant row only when its text is whitespace-only, it has no media and it is no longer streaming. Empty active responses and media-only responses stay visible. The previous empty-tool suppression remains separate. All original rows remain in cached history and the work journal, so presentation cleanup cannot erase a receipt or hide an attachment from recovery/export.

The UIKit transcript observes published reading scopes directly. Its coordinator captures the actual first visible row synchronously from the main-actor appearance publisher before message rows receive a new font. This differs from the requested restoration row, whose partially visible predecessor may be the reader's actual anchor. Offscreen targets are materialized before bounded layout/offset corrections; ordinary captures cannot replace a requested anchor with transient estimated geometry. Unchanged offsets do not schedule another scroll.

The real-window reading regression exposed failures in both scope observation and estimated row sizing. A new test changes only the published scope/font without replacing the hosting root; the old implementation failed six assertions. That negative test process was interrupted during teardown, so it is case-level evidence only. Three intermediate fixes still failed original position assertions and were corrected without changing those assertions. The final focused run on a dedicated iOS 27.1 simulator executed all four reading/TextKit methods with zero failures/skips in 3.573 seconds; its completed xcresult summary confirms four passes. The owned simulator was removed afterward. This is local UIKit evidence, separate from the rebased candidate's CI and USB acceptance.

Physical-session rollover and legacy transcript archival are a separate host integration. The optional message epoch is preserved metadata; this slice does not invent a physical epoch from a logical route or reset text. Reset/compaction markers and actual session IDs are retained, but cannot by themselves claim complete history acceptance. Live-to-history joining also requires actual producer evidence; run/turn/segment IDs are not guessed into message IDs. These items and actual six-backend/device acceptance remain pending in `PARITY.md`.

Verification separates exact-source macOS policy tests, actual App generic compilation, real iOS test execution in CI and physical-device evidence. `DEVICE-ACCEPTANCE.md` records the earlier main build only; it does not validate later transcript changes.
