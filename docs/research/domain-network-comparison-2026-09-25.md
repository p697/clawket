# 新旧域名基础网络对照测试

测试日期：2026-09-25，北京时间 22:40–22:45。此报告记录一次短时公共探针测量，不代表全国或长期可用性。

## 结论

本轮没有证据表明 `hello-clawket.com` 整体优于 `clawket.ai`。新入口在南宁联通、昆明移动较快，其余四个大陆节点较慢；新旧入口均出现超时。不能把域名注册时间作为大陆可用性的保证，也不能据此确认旧域名被墙。

## 方法

- 临时将 `relay.hello-clawket.com` 绑定到旧入口 `relay.clawket.ai` 所使用的同一个生产 Relay Worker，未部署 Worker 代码。
- 新入口通过临时 WAF 规则仅允许无查询参数的 `GET /v1/health`；本地验证健康检查为 200、`/ws` 为 403。
- 使用 Globalping 公共探针：大陆电信 AS4134、联通 AS4837、移动 AS9808 各两个节点，另加香港、日本各一个对照节点。大陆节点带有平台的 `eyeball-network` 标签，但不是用户手机或经过独立验证的家庭网络。
- 固定同一批八个探针，六轮 IPv4 HTTPS 对照，每轮近乎同时提交两个域名，轮间间隔约 20 秒。健康响应为 HTTP 200 且包含 `ok: true` 才记为成功。初始选点预热不计入六轮统计。
- 另测 A/AAAA 解析、TCP 443（每节点每域名 16 次）以及一轮 IPv6 HTTPS。共保存 168 条探针任务结果，包括预热。
- 控制 API 读取发生的本机 TLS 错误使用读取重试处理；第一轮已提交任务通过原 measurement ID 恢复结果，未丢弃失败样本。

耗时为成功请求总耗时的中位数，包含解析、建连、TLS 和响应；超时不纳入耗时中位数，单独计入成功次数。

大陆合计：旧入口 **35/36** 成功，新入口 **34/36** 成功。成功样本合并中位数分别为 821 ms 和 1089.5 ms，仅用于描述本组样本，不能外推全国。

排除可能受新域名冷解析影响的第一轮，旧入口仍为 30/30、新入口为 29/30；对应成功样本中位数为 887.5 ms、1083 ms。

三次失败均约 15 秒超时：旧入口第一轮南宁联通停在 TLS 阶段；新入口第一轮桂林电信完成 TLS 后等待首字节超时；新入口第二轮西安联通停在 TLS 阶段。成功请求也有抖动：旧入口南宁最高 12704 ms，新入口西安最高 6885 ms。

## DNS、TCP 和 IPv6

- A 查询：八个节点的新旧域名均返回 Cloudflare 地址。旧入口地址池为 `104.26.8.142`、`104.26.9.142`、`172.67.75.154`；新入口为 `104.21.86.143`、`172.67.220.147`。本次未观察到明显非 Cloudflare 解析结果，不能据此排除所有 DNS 干扰。
- AAAA 查询：每个域名均有七个节点返回答案；西安节点两者均为空答案、NOERROR。独立的 IPv6 HTTPS 测量中西安两者都成功，不能把一次解析结果等同于后续连接表现。
- TCP 443：大陆每域名 96 次探测均获得响应，报告丢包率为 0；部分单次耗时仍达到 1–3 秒。探测零丢包不等于没有 TCP 重传，也不证明长连接稳定。
- IPv6 HTTPS：大陆两者均为 4/6 成功。东莞节点两者均为本地 `ENETUNREACH`，不能算作域名不可达证据；南宁节点两者均连接超时。其余四个节点表现混合，未显示新入口一致领先。香港、日本对照均成功。

## 限制与建议

两个入口使用同一 Worker，但域名所在 Zone 套餐不同（旧 Pro、新 Free），解析地址池、边缘配置与缓存状态也不同。大陆样本中的响应 colo 涉及香港、欧洲和美国；该标记不能完整还原网络路径。结果不能单独归因于域名年龄。

本次仅验证基础网络和公开健康接口，未测试认证后的 WebSocket 持续收发、Bridge 恢复、Hermes、语音或完整 App 会话，也未覆盖高峰期、多天波动和用户实际 Wi-Fi。

双入口手动切换仍有价值，但默认新入口能改善大陆体验的假设尚未成立。后续验收应覆盖用户实际 Wi-Fi、蜂窝网络，以及同一设备的新旧入口长连接与消息往返对照。
