## Fixes found through acceptance

- Empty native threads do not necessarily have a persisted rollout. Recreate only never-submitted threads after restart; keep uncertain/accepted submissions tied to their native identity. Empty sessions remain renameable.
- Native reasoning selection uses a settings operation, never an accidental `/think` chat message; selection survives history refresh and Bridge restart.
- Recovered native tool/message IDs match live rows, preventing duplicate assistant chunks and tool completions after reopening during an approval.
- Same-Registry pairing refresh retains existing client identities and refuses to interrupt an active task. Default project files and ports isolate Preview from Production.
- A final real Bridge restart exposed owner-lease conflicts followed by a TLS failure inflating the network backoff past startup timeout. Lease waits no longer increment network-failure backoff; Relay startup permits 90 seconds with a longer bounded parent deadline. A deterministic lease-plus-TLS regression crosses the former 30-second boundary and recovers.
- Invalid primitive/null native JSON fails predictably; closed local sockets are removed from heartbeat tracking.
- Approval cards expose full long commands on demand and only advertise supported once/deny decisions. Composer retains model-only truncation and spacing.

## Explicit limits

No native Plan-mode toggle, desktop-task takeover/live desktop sync, application-layer end-to-end encryption, remote provider/account administration or Git publication UI. Native desktop/CLI histories are read-only until explicitly branched into an owned conversation. Unexpected native-process exit reports offline and requires a Bridge restart; it never silently repeats the last prompt.

Structured questions and file/network approvals have protocol tests, but device acceptance exercised real **command** approval flows, not every native interaction subtype. Custom-provider/API-key configuration is supported through native Codex configuration but was not a separate live authentication test. Windows/macOS Intel, physical iPhone, multi-day sleep/wake and adverse-network soak are not proven by this matrix. These boundaries must remain visible in release notes and follow-up planning.
