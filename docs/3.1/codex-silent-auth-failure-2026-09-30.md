## 归因与边界

1. **创建与消息传递成功，模型执行失败。** 两条消息和两个明确 `failed` 回合均在原生会话中。不能把这次无回复归因为消息未到电脑、项目未创建或 Xcode 权限未批准。
2. **旧 Bridge 漏掉了终止错误。** 原生失败没有普通 assistant item；旧历史路径只投影消息 item，手机只看到自己的消息。当前版本会把 failed-turn 元数据投影为稳定的系统提示，并提供旧 App 可读取的实时文本兼容信息。
3. **连通状态没有验证推理权限。** 两个 Bridge 均可返回 `modelReady=true`，原会话仍曾明确认证失败。当前 `health` 使用 `account/read(refreshToken:false)` 和模型目录；它证明原生 RPC 响应、存在缓存账户等条件，不能证明令牌刷新或模型推理成功。目录加载成功也不是模型访问授权验证。
4. **原生错误说明需要恢复登录，未证明触发动作。** 截图和原生状态不能确定负责人是否退出、切换过账户，或哪个长期原生进程持有失效认证状态。不能断言“用户切号”或“多个 Bridge 抢 token”。只检查了认证文件的时间/模式元数据，没有输出令牌或账户身份；没有尝试凭据迁移或自动退出登录。

官方资料说明 CLI/扩展共用缓存登录、正常使用时原生会自动刷新令牌；App Server 的 `turn/completed` 会明确携带 `failed` 状态和错误。参考：[原生认证](https://learn.chatgpt.com/docs/auth)、[App Server 生命周期及认证](https://learn.chatgpt.com/docs/app-server)。本次具体归因依赖上述本机会话与 Bridge 对比，而不是仅凭官方资料推测。

## 本次补强

- **Mobile 兼容旧 Bridge：** Codex 明确发出 `run_finished / error`，但没有系统提示、回复文字或附件时，补一个固定通用失败提示。已有错误说明保持原样；成功、取消、静默和失联不会被改成认证失败。无需新翻译，复用 19 语言已有提示。
- **Desktop 快速终止：** 终止快照可能先于 start-turn 确认到达。收到确切原生 turn ID 后，只核对当前 Bridge run 和已有 fresh 快照中的相同终止 turn，结束对应回合。过期快照、另一回合、`incomplete` 状态均不能结束当前运行。不会重发、创建新线程或获取第二 writer。
- 当前版本既有的原生 failed-turn 实时/历史映射已用原故障历史确认；这不是本次新实现。最新候选仍未对原故障 iPhone 做 UI 验收。

快照先到的边界有独立回归用例，未证明它是下午这两次失败的触发路径；原故障已确认的回显差异来自持续运行的旧 Bridge。

## 恢复与后续体验

先在原故障所用电脑原生实例确认登录是否仍失败；若仍失败，由负责人通过原生登录流程恢复。随后更新并重启**这一套 Codex Bridge**使新代码实际进入进程，保留原配对配置和原生线程；不需要重新扫码、删除会话或重发原先的 Archive 请求。手机的通用兜底需要更新 App，只有源码变化不会更新已安装 TestFlight。

验收用单独的新对话和无副作用文本：成功时确认真实回复；人为认证失败时确认手机出现提示，并在退出/重进后从历史保留。Bridge 接收、原生接收、运行结束和成功回复应按各自证据表述，不能把发送勾或“在线”视作执行成功。

不采用周期性强制 token 刷新作为本次修复：它会改变共享原生登录状态，不能代替失败处理，也不能用探活成功保证后续推理。后续可研究原生明确 auth 事件驱动的登录提示/用户主动重试；不得复制 Desktop 凭据、在手机索要原生令牌、自动重放结果未知的请求或因为一个历史失败永久锁住全部项目。

定向验证逐文件串行通过：Bridge `codex/service` 149、`codex/history` 9；Mobile `adapters/codex` 21、`useAdapterChatEvents` 16、`useChatController.adapter-events` 24，共 219 项。五个历史 v1 回放文件各自串行通过：`fixtures` 8、`historical-client-handler` 7、`historical-image-pipeline` 9、`legacy-bridge` 9、`live-replay` 8，共 41 项，包含原有 OpenClaw/Hermes 路径。Mobile 与 Bridge runtime 类型检查通过；文档/空白检查见进度记录。未跑全量套件。

本次只改代码与文档；未更新常用 Bridge 进程、原生认证、App 版本，未准备分发包、发布 OTA/npm 或部署云服务。截图中的 Archive 请求是故障证据，不是本次发布授权。
