# Native presentation

This directory owns reusable iOS presentation only. The app host owns backend capabilities, wire models, connection evidence, persistence and side effects. Do not infer delivery, authorship, permissions or readiness from prose, animation or socket state.

- Keep public presentation values and intents usable by the real app. Unsupported actions are hidden; temporarily unavailable actions explain their state. Do not ship fixture data or no-op controls.
- An approval-required connection status opens the exact host review identity; missing review metadata or capability cannot fall back to a reconnect or approval.
- Send and Stop are independent capabilities. A running task must not hide a supported send/queue action; the host supplies its label and owns queue behavior. Approval and question IDs are host-wide scoped presentation identities, mapped by the host to the exact backend request generation.
- Consent actions fail closed: the host supplies actual decisions and pending availability. Always emits prepare first; the host captures its runtime reference/token and publishes a unique immutable confirmation. Confirm/dismiss use that frozen confirmation ID; never retarget an open dialog. Question drafts emit explicit changes for synchronous host state and asynchronous persistence; dismissal never answers or cancels. Gate local editing separately, retain the exact submitting button, and distinguish accepted answers from retained drafts by typed host evidence. See `docs/native-ios/CONSENT-UI.md` for validation and binding.
- Work inspection preserves host-owned run/turn/input grouping and canonical order. IDs remain binding metadata, never product labels or diagnostics. Missing status stays unknown; clocks/output never prove success. Gate record/step/content inspection and text selection explicitly, mark bounded partial content, and reject ambiguous render identities. See `docs/native-ios/WORK-UI.md`.
- Session menus default to unsupported and use host review/confirmation IDs, never runtime references. Archived rows open their review instead of a chat; destructive decisions use a frozen host snapshot. Closing a native editor or sheet cannot mutate or retry. See `docs/native-ios/SESSION-UI.md`.
- Model controls default to unavailable, preserve exact opaque model IDs and host-provided current/unknown values, and keep the pressed action visible. Only actual advertised permission presets can repair an uncertain permission state; other unknown writes stay held. Confirmation events carry frozen host IDs. Recent/default recommendations and catalog search never alter write IDs. See `docs/native-ios/MODEL-UI.md`.
- The app owns the main-bundle catalog; see `docs/native-ios/LOCALIZATION.md`. Resolve app-authored defaults and dynamic labels with localization APIs; private label helpers may accept `LocalizedStringKey`. User/backend content, names, model titles, commands and filenames remain verbatim.
- Preserve iOS 16.4. Guard iOS-only views so the package's macOS core checks compile. Use system navigation, sheets, menus, text selection and semantic colors/type; preserve the Clawket cat identity.
- Roster selection is navigation state, separate from the concrete conversation. List normalization/Back cannot clear or replace a secondary-session route; programmatic route updates synchronize sidebar state directly. Keep the List tree stable across readiness changes; capability-gated roster refresh is an explicit native toolbar action.
- Keep draft ownership outside view lifetimes. Compact/expanded editing must retain the same native text view, marked text and selection. Transcript IDs and reading anchors must survive streaming, pagination and reconciliation.
- TextKit views take their horizontal size from the window/row proposal, including compact phones; their natural single-line width must not push messages or composer actions offscreen. Keep real hosting/table-cell geometry checks alongside device evidence when changing these constraints.
- Native builds and simulator/device checks require the shared leases. Record simulator, fixture and real-backend evidence separately in `docs/native-ios/` through the program owner.
