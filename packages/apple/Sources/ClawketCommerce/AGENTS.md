# Native commerce policy

Root and Apple package instructions apply. Preserve Mobile Pro policy and its actual current consumers. Keep community access separate from paid ownership, legacy one-time grace and the free connection slot. Only the configured purchase SDK's verified current customer grants paid access; app display caches never do.

This package contains pure policies and bounded allowance storage. The iOS host alone configures the pinned RevenueCat SDK after resolving purchase identity. Same-bundle identities come only from validated Upgrade staging; QA must never log in, alias or restore the store app's identity. Unknown allowance writes stop until verified cold recovery. Corrupt storage does not mean missing or a renewed grace period.

Offerings use real products/prices and opaque current references. Purchase, restore and redemption require explicit user intent; never replay checkout or treat system presentation, pending payment, historical product purchase or a scheduled plan change as new entitlement. Closing retires only its continuation; SDK-delivered genuine access may still reconcile. No transaction IDs, receipts, customer identities or native errors enter diagnostics. Actual store purchases and release actions require the owner's explicit acceptance path.
