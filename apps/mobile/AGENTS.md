## Product architecture

- The app has one root native stack with content-owned headers. There is no bottom navigation; `@react-navigation/bottom-tabs` is a forbidden legacy dependency.
- Backend identity answers which product is connected: `openclaw` or `hermes` (with YouMind Sprite represented by its dedicated adapter). Transport identity answers how it connects: local, relay, tailscale, cloudflare, or custom. Never model Hermes or Preview as a transport.
- UI and feature code consume `src/connection/` through the registry, adapters, descriptors, and capability metadata. Do not import wire transports or branch on backend in screens.
- Only the active connection owns a live adapter. Other connections remain visible through cached roster/session state. Switching must stop the old adapter before the new one is authoritative.
- Unsupported actions are hidden or locked from centralized capabilities; do not issue a request and wait for an `unsupported` error.
- Keep the OpenClaw and Hermes paths equally complete. Shared chat, storage, pairing, retry, and lifecycle changes require tests for both where applicable.
- Android edge-to-edge chat uses controller keyboard padding as iOS does; do not rely on `adjustResize` alone. Reserve inline message metadata with nonprinting fixed-width spaces, never transparent clock digits inside selectable text. Pairing error matching must distinguish rate-limit phrases from words such as `Generate` in expired-code instructions.
- Hermes model selection is global-scoped. Do not add per-session Hermes model state.
- Live roster work phases belong to the connection runtime, not mounted chat controllers. Publish phase changes only, clear them on terminal/disconnect, and never persist them or treat them as health evidence. Local sends stagger reply presentation by 1000ms without delaying transport; history entry and reduced motion remain immediate. The hold remembers render identities, so a post-run refresh that swaps backend ids never hides the previous reply.
- Recycled message rows reset Reanimated shared values in the commit/layout-effect phase, never during render; non-animated history rows must restore full visibility.
- Preserve one chat runtime. Recovery, foreground, reconnect, watchdog, and final reconciliation must share coordination rather than independently probing history.
- Tool boundaries settle the preceding text row even while the run continues; only the current tail stays streaming. Known reply clocks remain visible from the first text, with no invisible metadata footer. Live/history matches preserve live row identity and cannot add a second placeholder; the Thread's own reply placeholder carries the controller's `pendingReplyRenderKey`, so the first streamed row of a run the phone did not start takes over its cell. Quiet tools are not completed by a text-silence timer: use backend run evidence, and require a failed health probe before recovery reconnects. The 22 s inactivity fallback defers to confirmed activity (a watchdog `hasActiveRun` re-arms it) and never tears down live rows while the backend reports the run. Transient presentation cleanup is idempotent.
- Adapters declare message `textMode`: OpenClaw supplies whole-run snapshots; Hermes, YouMind and local-model supply deltas. Never infer repeated delta tokens from string equality. Subtract committed text from snapshots at tool boundaries, reconcile live/history rows within the same user turn, and reconstruct those boundaries from recovery history. Correct old cumulative presentation rows only when canonical split history confirms the isolated text.
- Background OpenClaw children may emit only `agent` assistant/lifecycle events: capture cumulative assistant text and settle explicit end/error/abort for child session keys. Main conversations must still wait for authoritative `chat` finals; never treat `finishing` as completion.
- Completed child-run cards are local execution records, not expiring activity hints. Preserve terminal text and failure state, cache up to 100 records per connection/Agent/parent session, and open the retained result when the child session is gone. Never persist a live run as completed or infer ownership against an explicit different parent.
- Gateway history may coalesce multiple CLI tool calls/results inside assistant or user content. Project every identified block at the adapter boundary; preserve call IDs, errors and outputs without turning tool-result envelopes into user bubbles.
- Channel messages carry optional `MessageAttribution` independently of model role. Preserve it through history, recovery, cache and favorites; external participants render incoming with identity and no outgoing receipt. Only exact local send evidence establishes self; owner flags, names and mentions never do. Scope identities by connection/channel/account, and never text-match different or unknown participants. Missing photos use stable identity-colored initials from existing light/dark accent scales; participant conversations add a localized Agent badge without an extra avatar border. Keep bubble colors unchanged and never send channel credentials to the phone. See `docs/3.0/25-message-participants.md` at the repository root.

### Connection and protocol safety

- The copied pairing prompt stays close to the original length: exact environment command, open-source CLI purpose, explicit authorization to return the printed temporary code in this conversation, and code/backend-only output without other credentials. Keep all locales aligned.

- Treat socket open, a valid frame, handshake completion, and backend ready as distinct stages. Successful health evidence resets reconnect backoff; raw WebSocket open does not.
- Relay pong expiry applies only when `relay.client-pong.v1` was negotiated. Legacy clients are not expired merely for application-level silence.
- Check the final serialized frame on every path. Exactly 8 MiB is valid; larger frames fail locally as `frame_too_large` and are not sent.
- Preview is an isolated OpenClaw Relay service environment. Debug mode selects it for new official pairing; it remains `backendKind=openclaw` and `transportKind=relay`.
- Official Production and Preview invitations are environment-checked. Custom/self-hosted Registry QR payloads remain supported and are not classified as official.
- Pairing links and six-character codes must decrypt/resolve into the same backend-aware claim/save/reconnect path as legacy QR pairing. Never persist fragment keys, plaintext invitation payloads, raw passwords, or transport credentials in descriptors or logs.
- Keep the client's own pairing handshake separate from owner device/node approvals. Owner pair requests are connection-wide, never session-owned, and must not enter thread history or message cache. Thread pair cards explain the connection request and show only pending entries; acknowledged, rejected or expired entries disappear while in-flight and failed requests stay actionable. Keep resolution tombstones to reject stale events.
- Scope every live or cached Agent identity by both connection ID and Agent ID. A connection switch must render a neutral identity until the new scope is authoritative and must never persist the previous connection's name, emoji, or avatar.
- Agent usage and profile cost requests include the selected Agent identity. Hermes strips the UI identity at its adapter boundary to preserve its single-Agent wire contract; never retry an owner-scoped OpenClaw query as a global query. OpenClaw adds the phone IANA timezone and UTC offset at its adapter boundary for both usage methods; only an explicit unexpected `timeZone` property error may downgrade to the offset, never drop the Agent owner or silently revert to UTC. Hermes keeps its native single-Agent/local-calendar request contract. Profile, details, and share posters use the same completeness resolver: missingCostEntries means partial dollars or unpriced tokens, never a known zero. Mounted usage/profile pages refresh at local day/zone changes and foreground; cache identity includes the calendar/zone.
- Store OpenClaw device tokens by both connection scope and role. Operator and node credentials must never overwrite or invalidate each other; node lookups must not fall back to legacy operator tokens.
- OpenClaw Relay capability requests use the Gateway-compatible `connect.params.caps` array, never a new top-level `meta` field: old Bridges forward requests unchanged. Missing response capability metadata keeps legacy behavior; advertise caps again on later handshakes so cached legacy results do not hide a Bridge upgrade. Retain one explicit schema-error downgrade for older protocol implementations; network/auth failures never trigger it.
- Bridge diagnostics may read the CLI version only from a negotiated OpenClaw Relay connect response or Hermes health. Direct OpenClaw and legacy peers report no Bridge version; never relabel the Gateway's `server.version` as a Bridge version.
- A committed connection removal must not await the fallback backend handshake. Reset removed connection routes to the current Roster/Onboarding root; never keep deleted profiles in the back stack or publish their roster/error state.
- Connection removal clears only that connection's credentials, cache generations, roster cache, unread watermarks, cron failure acknowledgements, and thread activity snapshots. Roll back storage migrations atomically on failure.
- Keychain outlives the bundle on iOS (owner report 2026-09-19: a deleted-and-reinstalled app booted into its old connection with an empty roster and a locked add action). `useFreshInstallGate` runs before `AppRoot` mounts: `install-state.ts` reads the AsyncStorage marker `clawket.installMarker.v1`; no marker plus no `clawket.*` sandbox key means a fresh install and triggers `resetForFreshInstall` (`ConnectionRuntime.removeAllConnections` — every record through the normal removal path, YouMind sessions, then `ConnectionStore.clearPersisted` for the current, rollback and legacy snapshots — plus `StorageService.clearLocalPreferences`); no marker with sandbox data is an upgrade and only writes the marker; unreadable storage fails closed to `existing`. The device identity and the Pro entitlement / grace record beside it are never reset (`06-paywall-and-growth.md` §宽限期). Do not read Keychain-backed preferences or start the connection runtime before the gate resolves.
